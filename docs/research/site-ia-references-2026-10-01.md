## 0. 방법과 한계

- 읽기만 했다. 로그인, 가입, 생년월일 입력, 결제, 폼 제출은 하지 않았다.
- 공개 HTML을 그대로 받아(curl) 제목, 설명, canonical, hreflang, JSON-LD `@type`, 제목 구조(h1~h3), 푸터 링크를 스크립트로 뽑았다. sitemap.xml과 robots.txt도 받았다.
- 포스텔러 한국어 웹(forceteller.com)은 브라우저에서 그려지는 앱(빈 `#root`)이라 HTML에 본문이 없다. 메뉴·푸터는 공개 자바스크립트 번들의 문자열로 확인했다(렌더링된 화면은 못 봄).
- 이 문서에는 경쟁사 주소·전화번호를 옮기지 않았다(필요 없고, 우리 원칙과도 맞지 않음). 문장은 모두 의역이고 직접 인용은 하지 않았다.

## 2. 사주핑

**IA 지도**
- 상단: 홈 · 사주 체험 · 블로그 · 리뷰 · 가이드 · FAQ · 언어 전환(KO/EN/JA/繁中) · 앱 다운로드.
- 푸터(12개): 사주란? · 사주핑이란? · AI 사주 분석 원리 · 홈 · 블로그 · 리뷰 · 사용자 가이드 · FAQ · 팀 소개 · 개인정보처리방침 · 이용약관 · RSS, 그 아래 사업자 표기.
- 모든 설명 페이지 끝에 다른 설명 페이지로 가는 링크 3개(원리 → 소개 → 리뷰)와 앱 다운로드 띠가 붙는다.

**신뢰를 만드는 것**
- 원리 페이지를 "계산 층"과 "해석 층" 둘로 나눠 설명하고, 세 번째 절을 **한계**에 쓴다(시간을 모르면 해상도가 낮다, 절기 경계는 경고가 필요하다, 모델은 내 상황을 직접 보지 못한다). 장점만 나열하지 않는 것이 신뢰 장치다.
- 소개 페이지는 "하는 일 / 하지 않는 일"을 나눈다. 배우자·합격·죽음을 확정하지 않는다고 적는다.
- 검증 안 된 효과 수치를 **일부러 싣지 않았다**고 밝히는 절이 있다. 후기는 통계가 아니라는 구분도 한다.
- 리뷰 페이지 끝에 "후기는 어떻게 실리나요"(출처, 별도 수집 안 함, 삭제 요청 방법)를 둔다.

**결제 전 의심을 줄이는 것**
- FAQ 첫 문항이 "무료인가요?". 이어서 무료 재화 충전 규칙, 무료와 유료의 차이(모델 성능), 구독 취소 경로(스토어별 단계)까지 적는다.
- "ChatGPT로 보는 사주와 뭐가 다른가요?"를 FAQ와 원리 페이지 양쪽에서 다룬다. 다만 "일반 AI는 계산이 부정확하고 매번 답이 다르다"처럼 단정이 섞여 있다.
- 홈에 평점·리뷰 수·사용자 수 숫자 띠를 둔다(앱스토어 기준).

**기능 발견**
- 사용자 가이드: 상단 "USER GUIDE" 표지 → 제목 → 카테고리 칩 5개(시작하기 · 사주·운세 · 궁합·관계 · 활용 팁 · 혜택) → 분류마다 제목과 한 줄 설명 → 카드(이모지 아이콘, 제목, 한 줄 부제, NEW 배지, +) → 펼치면 번호 단계와 TIP. 끝에 "더 궁금하면 FAQ, 문의 이메일".
- 홈에 "이렇게 물어볼 수 있어요" 대화 예시, 앱 안에는 추천 질문 목록.

**SEO**
- 모든 페이지 canonical, hreflang 5종. sitemap-index → sitemap-0.
- 홈: WebSite + Organization(창업자, 우편 주소 포함) + MobileApplication(가격 0 Offer). /home: MobileApplication + FAQPage 4문항.
- /faq: FAQPage 20문항. /ai-saju, /what-is-sajuping: Article. /saju-ran: Article + FAQPage. 블로그 글: BlogPosting + BreadcrumbList, 본문 끝에 FAQ 절.
- /guide와 /reviews에는 구조화 데이터가 없다.

## 3. 사주도령

**IA 지도**
- 홈이 곧 메뉴다. 대표 버튼에 가격이 붙어 있고(풀이 이름 · 가격), 관계·기타 풀이가 카드 목록으로 이어진다. 무료 항목(귀인 지도, 오늘의 운세, 캐릭터 진단)이 유료 목록 사이에 끼어 있다.
- 햄버거 메뉴: 보유 이용권 · 결제·이용내역 · 도령의 일지 · 사주관리 · 내 프로필 · 새로 바뀐 것 · 알리기 · 문의 · 약관 · 개인정보.
- 푸터: 운영주체 안내 → 상호·대표·사업자등록번호·통신판매업 신고번호 → 고객센터(이메일, 문의하기) → "사주도령 알아보기"(사주·궁합 안내, AI 사주 풀이, 궁합 풀이, 음력 사주, 운영주체·캐릭터 안내, 약관, 개인정보).

**신뢰를 만드는 것**
- 운영주체 페이지에서 캐릭터(두 도령)와 운영 회사를 한 페이지에 설명하고, 이름이 비슷한 다른 서비스와 관계없다고 홈·메뉴·푸터에 반복한다.
- AI 풀이 안내는 세 절: 계산과 해설을 나눈다 → 좋고 나쁨보다 작동 방식을 본다 → 참고할 점(전문 판단을 대신하지 않음).
- **푸터에 우편 주소가 없다.** 상호·대표·사업자번호·통판번호·이메일만으로 사업자 표기를 한다. 우리 규칙(주소 없음)과 같은 모양의 실제 사례다.

**결제 전 의심을 줄이는 것**
- 모든 버튼에 가격이 적혀 있다. 누르기 전에 얼마인지 안다.
- "받은 풀이 해설은 무료, 새 질문은 질문권" 한 줄을 홈에 둔다.
- 약관에 결과가 안 생기면 자동 환불·이용권 복구, 이용권 유효기간을 적는다(FAQ는 없음).

**기능 발견**
- 홈 목록 + 메뉴의 "새로 바뀐 것". 가이드 5편이 SEO와 기능 소개를 겸한다.

**SEO**
- canonical, hreflang 없음. JSON-LD는 홈의 WebApplication + Offer 하나.
- sitemap 13개(홈, 풀이 메뉴 5, 가이드 6, 로그인). robots가 결과·결제·프로필·일지 경로를 막는다.

## 4. 오늘의 마음 타로

**IA 지도**
- 홈: 제목 → 시즌 콘셉트 묶음 → "지금 어떤 마음에 가까운가요?"(관계 · 일과 성장 · 생활과 회복 · 결정과 흐름) → 진행 3단계 설명 → 심층 해석 가격 → 가이드 글 → FAQ 4문항.
- 푸터(11개): 서비스 소개 · 자주 묻는 질문 · 스프레드 안내 · 문의 · 콘텐츠 운영 원칙 · 개인정보처리방침 · 이용약관 · 면책 안내 · 안전 정책 · 상품/가격 · 업데이트, 그 아래 사업자 표기와 "오락·자기성찰 목적" 한 줄.
- 콘텐츠 층: 카드 78장 페이지, 주제별 타로 메뉴 38개, 블로그 19편, 타로 가이드 7편.

**신뢰를 만드는 것**
- 소개 페이지에 "해석 문장은 어떻게 만들어지나요"와 "이 서비스가 하지 않는 것"(질병·수명 판단, 결과 보장, 남의 속마음 단정, 불안을 키워 반복 이용 유도)을 둔다.
- 콘텐츠 운영 원칙 페이지: 카드 해설을 직접 썼다, 카드 사이 문장 중복을 자동 검사한다, AI 심층 해석의 역할, **광고·제휴 표시 기준**, 오류 제보 경로.
- 업데이트 페이지(변경 이력)로 살아 있는 서비스임을 보여 준다.
- 안전 정책(자해·위기, 미성년자 보호, 신고 절차)과 면책조항을 따로 둔다.

**결제 전 의심을 줄이는 것**
- 상품/가격 페이지에 "구매 전 확인하면 좋은 점": 무료 리딩으로 결을 먼저 확인하라, 같은 질문을 여러 번 보려고 사지 말라, 이용권 기한이 없으니 서두를 필요 없다.
- FAQ 19문항 중 결제 전 의심에 답하는 것: 회원가입 필요 여부, 무료 횟수, 결과 저장·공유, 정확도, 다시 뽑으면 왜 다른가, 무료와 심층의 차이, 이용권 기한, 결제 후 결과가 안 보일 때, 입력한 질문 처리, 광고 표시, 리딩 내용의 광고 사용 여부, 미성년자.

**기능 발견**
- 마음 상태로 고르는 메뉴(주제가 아니라 기분으로 진입), 시즌 콘셉트, 스프레드 안내 페이지(카드 수에 따라 무엇이 달라지는지).

**SEO**
- canonical + hreflang(ko-KR, x-default). sitemap 155개 모두 lastmod.
- 거의 모든 페이지에 BreadcrumbList. FAQPage는 홈·FAQ·카드·타로 메뉴·블로그 글·스프레드에. 홈과 /products에 Product + Offer + MerchantReturnPolicy. /about은 AboutPage, /contact는 ContactPage, 가이드 목록은 CollectionPage + ItemList, 카드 페이지는 Article.
- robots가 /api/, /payment/ 를 막는다.

## 5. 포스텔러

**IA 지도**
- 한국어 웹은 브라우저에서 그리는 앱이다. 번들 기준 경로: 테마·콘텐츠 상세, 결과, 충전, 쿠폰, 선물, 이용권, 이벤트(/leaflets), 공지사항(/notice), 고객센터(/help), 약관(/policies/…).
- 사이드 내비게이션 하단에 약관·개인정보 링크와 아주 작은 글씨의 사업자 표기.
- 회사 사이트(운칠기삼): 회사 소개 · 보도자료 · 채용 · 서비스(만세력 웹, 운세 테스트, AI 베타, 영어 사주 가이드) · 비즈니스(제휴·광고 소개서) · 연락처.

**신뢰를 만드는 것**
- 회사 사이트에 이름을 건 운세 전문가 22명 명단, 언론 기사, 투자사. 제품 웹이 아니라 **회사 사이트가 신뢰를 맡는다**.
- AI 점집 서브도메인은 공유 미리보기 문구에 누적 상담 수를 넣는다.

**결제 전 의심을 줄이는 것**
- 웹에서 공개적으로 읽을 수 있는 FAQ·가격 안내를 찾지 못했다(앱 안 고객센터로 추정).

**SEO**
- 한국어 웹: 본문 없는 앱 껍데기, sitemap 없음(sitemap.xml이 앱 화면을 돌려줌), robots는 전부 허용, JSON-LD 없음. 검색 노출은 사실상 앱 브랜드와 서브도메인에 기댄다.
- 영어 서브도메인은 sitemap이 있고 긴 가이드 페이지(띠별 운세)를 SEO용으로 둔다. 언어별 별도 도메인을 hreflang으로 묶는다.

## 6. 네 곳에서 보이는 공통 패턴

1. **푸터가 신뢰 목차다.** 넷 모두 약관·개인정보 외에 "무엇인가 / 어떻게 만드나 / 누가 운영하나"로 가는 링크를 푸터에 둔다. 사주핑과 오늘의 마음 타로는 10개가 넘는다.
2. **원리 설명은 "계산 → 해석 → 한계" 3단이다.** 사주핑과 사주도령이 거의 같은 뼈대를 쓰고, 한계 절이 있는 쪽이 더 믿음직하다.
3. **"하지 않는 것" 목록**이 소개 페이지의 핵심이다(보장, 남의 마음 단정, 건강·수명, 불안 유도).
4. **FAQ는 4분류 15~20문항**, 첫 문항은 무료 여부. 결제·개인정보·정확도·재뽑기가 반드시 들어간다. FAQPage 구조화 데이터는 FAQ가 있는 둘 다 쓴다.
5. **기능 가이드는 칩 + 아코디언**(사주핑). 문서형(사주도령)보다 기능 수가 많을 때 훑기 좋다.
6. **숫자로 설득하는 곳과 숫자를 거부하는 곳이 갈린다.** 사주핑 홈과 포스텔러는 사용자·상담 수를 내세우고, 사주핑 소개 페이지와 오늘의 마음 타로는 검증 안 된 수치를 싣지 않는다고 말한다.
