## 요약

입구를 **"타로로와 사주주가 나한테 별명을 붙여 주는 곳"**으로 바꾸자.

- **홈 첫 화면에는 훅을 하나만 둬.** "연락할까 말까? 카드 한 장 뽑아 봐"를 걸고, 로그인 없이 바로 되는 지금의 한 장으로 보내.
- **카드를 뒤집으면 타로로가 별명을 붙여.** 별명은 AI가 쓰지 않아. 카드 원소로 정하는 규칙이라 같은 카드면 늘 같은 별명이 나와. 그래서 친구랑 비교하고 공유할 수 있어.
- **비로그인 방문자도 결과에서 받는 게 생겨.** 3장 타로는 지금 로그인 벽 앞에서 카드 그림만 받는데, 그 자리에서 "설렘 엔진 과열형" 같은 타입 판정을 받게 돼.
- **사주 쪽은 승인된 등급 카드를 그대로 써.** 사주주의 "올해 무슨 달"이 그 역할을 해.
- **잠금, 결제, 결제 뒤 화면에는 실제 값만 보여 줘.** 실제 개수("소제목 12개 중 1개 공개"), 실제 가격, 실제 날짜를 쓰고, 연애와 궁합 상품을 앞에 둬.

**바꿀 것 상위 5개**
1. 홈 훅 하나로 정리: 첫 화면에 금색 버튼은 "한 장 뽑기" 하나만 남겨(B1).
2. 로그인 화면 제목 바로잡기: 맛보기를 보러 왔는데 "로그인하고 전체 풀이 보기"가 뜨는 문제를 고쳐(B1).
3. 타로 타입 이름: 지금의 한 장 12종(B1), 3장 20종(B2). 전부 규칙으로 정하고 모든 경우를 덮어.
4. 타입·등급 공유 카드: 1200×630과 9:16을 만들고, 친구와 비교하는 한 줄을 붙여(B2, B4).
5. 잠금·결제 화면: 실제 개수를 보여 주고, 내용을 가격보다 먼저 두고, 견본 링크와 캐릭터 한 줄을 넣어(B1, B3).

**번들 순서**
- B1 첫 화면, 로그인 문구, 지금의 한 장 별명, 잠금 개수 (하루)
- B2 3장 타입, 공개 순간, 공유 페이지
- B3 잠금 시트, 결제 화면, 결제 뒤
- B4 등급 카드 연결, 무료 테스트 3종 말투
- B5 인연 점수 구간 이름, 초대 첫 화면
- 측정 트랙 M은 1일차에 개인정보 공지를 띄우고 8일차에 켜.

## 2. 리뉴얼 콘셉트와 팔폭 말투

### 2.1 콘셉트(한 단락)
스타로그 입구는 **타로로와 사주주가 나한테 별명을 붙여 주는 곳**이 돼. 들어오자마자 고민 하나("연락할까 말까")로 카드 한 장을 뽑아. 로그인하지 않아도 답 한 줄과 타로로의 별명을 바로 받아. 별명은 AI가 쓰지 않고 뽑은 카드의 원소와 기울기로 정하는 규칙이야. 그래서 같은 카드면 늘 같은 별명이 나오고, 친구랑 비교하거나 공유하기 좋아. 사주 쪽은 사주주가 올해 무슨 달인지 등급을 붙여 줘(승인된 등급 카드). 놀림은 카드 배치와 상황만 겨냥하고, 놀린 뒤에는 꼭 그 사람 편을 들어. 더 알고 싶어지는 순간이 있어. 왜 이 타입인지, 왜 이 등급인지, 나머지 소제목 11개에 뭐가 있는지 궁금해질 때야. 그때 실제 개수, 실제 가격, 실제 날짜만 보여 주고 결제를 권해. 돈 흐름은 무료 → 1,900원(등급 이유) → 2,900원·4,900원 → 7,900원(궁합) → 14,900원·세트 순서고, 연애와 궁합을 앞에 세워.

### 3.4 타로 타입 규칙: 결정적이고 모든 경우를 덮음

**매핑 원천(전부 코드 안에 이미 있음)**
- 원소: `packages/core/src/tarot/cards.ts:5-16`(CardDef.element). 메이저 22장은 `:27-50`, 수트 4종은 `:52-57`이야. 수트는 완드=불, 컵=물, 검=바람, 펜타클=흙이야.
  - 78장은 불 21, 물 19, 바람 19, 흙 19장이야 [측정].
- 기울기(지금의 한 장): `lib/decision.ts:9`의 go·wait·rethink. 값은 `lib/decision.generated.json`에서 카드×정역마다 하나씩 나와. 덱 그림을 바꿔도 같아.
- 덱: 78장 균등, 역방향 비율 0.3이야(`packages/core/src/tarot/draw.ts:23`, `:68-78`). 서버가 섞어(`app/api/tarot/draw/route.ts`, 로그인 불필요).

**3장 타입 알고리즘**
`lib/tarotType.ts`의 `spreadType(cards)`야.
1. 세 장의 원소 개수를 센다. 자리 순서와 정역은 보지 않는다.
2. 한 원소가 3장이면 `{원소}3`(순수 판, 4가지)
3. 한 원소가 2장이면 `{많은 원소}2-{나머지}`(12가지)
4. 셋이 다 다르면 빠진 원소로 `no-{원소}`(4가지)

세 장에 원소 4가지면 나올 수 있는 조합은 C(6,3)=**20가지**야. 표의 20개가 전부를 정확히 한 번씩 덮어. 확률을 다 더하면 1.000000이야 [측정].

**배지(사실만, 여러 개 붙을 수 있음)**

| 배지 | 조건 | 일어날 확률 [측정] |
|---|---|---|
| 희귀 판 | 순수 3장 | 불 1.75%, 물·바람·흙 각 1.27% |
| 메이저 | 메이저 2장 이상 | 19.0%. [C(22,2)·56 + C(22,3)] / C(78,3) |
| 역방향 | 역방향 2장 이상 | 21.6%. 3·0.3²·0.7 + 0.3³ |

**지금의 한 장 타입**
`nowType(cardId, orientation)`은 `now-{원소}-{기울기}`야. 원소 4가지 × 기울기 3가지 = 12가지야.
- 카드 156면(78장 × 정역)이 전부 12가지 중 하나로 가.
- 12가지가 모두 실제로 나와. 가장 적은 건 흙·지켜보기 8면이고 가장 많은 건 불·가 보기 20면이야 [측정].

**비교 규칙**(친구와 나, 4.2절)
- 주 원소를 정해. 1장이면 그 원소야. 3장이면 순수 판과 2+1 판은 많은 원소이고, 셋 다 다르면 "골고루"야.
- 두 주 원소의 관계는 골든 던 원소 상성으로 정해. 원소 배정의 출처도 같은 전통이야(`cards.ts:22-26` 주석).
  - 같은 원소
  - 서로 돕는 원소: 불·바람, 물·흙
  - 정반대 원소: 불·물, 바람·흙
  - 옆 동네 원소: 불·흙, 물·바람
  - 한쪽이 골고루
- 관계는 대칭이야. 순서를 바꿔도 같은 문구가 나와.

**사주 등급 별명과는 이렇게 같이 있어**
- 타로 타입은 "이번 판", 사주 등급은 "올해", 인연 구간은 "두 사람"이야.
- 이름 문법이 달라서 섞이지 않아(2.6).
- 한 화면에 같이 나올 때는 위에서 아래로 타로 → 사주 순서로 따로 쌓아. 둘을 합친 점수는 절대 만들지 않아.

**표시 원칙**
- 별명은 화면에만 써. 서버나 AI로 보내지 않아.
- 별명이 다른 사이트 문구와 겹치는지 7절 B2의 리뷰 단계에서 검색으로 확인해(R11). 내가 새로 쓴 거라 겹칠 일은 없다고 보지만 [추정]이야.

### 3.5 공개 순간: 99%에서 멈추는 가짜 로딩 대신
- **타입 판정은 계산이 즉시 끝나.** 그래서 "기다리는" 연출은 만들지 않아. 이미 나온 사실을 **차례로 펼치기만** 해. ① 원소 개수, ② 메이저·역방향, ③ 별명 순서고, 0 / 300 / 600ms에 하나씩 나와서 0.9초 안에 끝나.
  - "세는 중", "분석 중" 같은 진행형 문구는 안 써. 아직 계산 중인 것처럼 읽히니까.
  - 눌러서 건너뛸 수 있어. 움직임을 줄이는 설정이면 한 번에 다 보여 줘.
  - 화면 읽기 프로그램에는 마지막 별명만 읽어 줘(aria-live polite).
- **맛보기를 실제로 기다릴 때(로그인 뒤 보통 10초 안팎)**는 기존 막대가 그대로 진짜 진행을 보여 줘(`lib/reading/progress.ts:222-230`, `:239`). 위에서는 이미 나온 타입 카드가 기대감을 만들어. 맛보기가 0.9초보다 먼저 오면 남은 펼침은 건너뛰어.
- **전체 풀이를 기다릴 때(약 1분)**는 `GeneratingState`의 카드 넘김 첫 장을 "이번 판 타입 · 설렘 엔진 과열형"으로 바꿔. 진짜 값이야. 둘째 장부터는 기존 "지금 적는 중"과 가이드 요점이야(`components/tarot/GeneratingState.tsx:61-63`).
- **등급 카드**도 계산이 즉시라 로딩 연출을 넣지 않아([등급카드]의 흐름 그대로).
- 진행 막대를 멈췄다가 결제를 받는 장치(Starla)는 쓰지 않아([등급] "가져오면 안 되는 것").

### 3.6 잠긴 내용 미리보기: "N개 중 N개 공개"를 실제 개수로
- 서버가 개수를 정해서 보내. 맛보기 응답에 `tocTotal`, `tocOpen`, `tocPartial`을 붙이고, lockedToc를 만드는 곳에서 바로 계산해.
  - 타로: `lib/ai/generate.ts:60`. 전체는 `tarotLockedToc(ctx).length`야. 3장이면 12개고, 맛보기에 둘째 카드가 있을 때만 앞부분 1개를 세.
  - 사주: `lib/ai/generate.ts:143`. 전체는 `SAJU_LOCKED_TOC.length` 11개야(`lib/ai/prompts/saju.ts:363`, `lib/sajuPrologue.ts:12-22`).
  - 주제 사주: `lib/ai/generate.ts:396`. 전체는 `topicLockedToc(topic).length`야.
  - 프리미엄 미리보기: `lib/ai/generatePremium.ts:56`, `:124`, 신년운세 쪽. 같은 필드를 붙여.
  - 예전 맛보기(teaserCache)에는 필드가 없어. 그때는 지금 문구로 돌아가.
- 화면 문구

| 상품 | 문구 |
|---|---|
| 타로 | 소제목 12개 중 1개 공개 · 1개는 앞부분만 · 전체 약 2,000자 |
| 사주 | 소제목 11개 · 맛보기에서는 이름과 요약을 먼저 보여 드렸어요 · 전체 약 2,500~3,000자 |
| 등급 풀이 | [등급카드] B-7 "이 등급인 이유 · 5개 중 0개 공개" 그대로 |

- 사주는 0개를 "0개 공개"라고 쓰지 않고, 실제로 받은 것(이름, 요약)을 적어. 거짓은 아니고 받은 걸 먼저 말하는 방식이야.
- 잠긴 문장을 ●로 가려 흉내 내지 않아. 결제 전에 풀이가 만들어지지 않으니까([등급] "조건이 붙는 두 가지"). 소제목과 개수만 보여 줘(지금 `LockedToc`와 같은 원칙, `components/tarot/LockedToc.tsx:10`).

### 5.2 정직한 문구 패턴
- **열리는 것 + 실제 개수 + 실제 가격 + 환불 규칙.** 예: "남은 11개 · 2,900원 · 열기 전 7일 안 전액 환불"
- **날짜 마감은 진짜 날짜만 써.** "오픈 기념 타로 전체 풀이 무료는 11월 30일까지"는 기존 `OPENING_LAST_DAY`를 쓰고, 12/1에 저절로 사라져. 세트는 "12월 1일부터"야.
- **위로 문장과 판매 문장은 떼어 놔.** [등급] "가져오면 안 되는 것"의 고트사주 배치 비판을 따른 거야. 등급 고정 문구와 다음 풀이 줄 사이에 다른 칸을 둬([등급카드] B 9번과 같아).
- **할인 표기는 세트의 실제 차액만 써.** 취소선 정가는 안 써.

### 5.3 연애와 궁합을 앞으로
- 홈 훅이 연애 질문이야(T1).
- 3장 연애 주제 결과에 궁합 링크를 둬(B3).
- 별자리 인연 점수 → 궁합 "이유"(B5)
- 결제 뒤 연애 질문 → 궁합 먼저. 기존 그대로야(`LocalChapter.tsx:242`).
- 질문 만들기의 "누구" 순서(`lib/flowState.ts:14-19`)는 **안 바꿔.** 이미 익숙한 흐름이라 그래 [추정].
