## 1. 한 줄 정의

사주와 타로를 **하나의 "나의 이야기"에 장(章)으로 쌓아 보여주는** 반응형 웹앱. 리딩의 정확성과 구체성이 본질이고, 이야기 형식·친구 참여·읽을거리는 전파력과 차별화를 위한 장치다.

## 3. 범위

### MVP에 넣는다

- 홈, 질문 만들기, 타로 3장 리딩, 사주(명식·요약·심층), 하이브리드
- 나의 이야기: 장 타임라인, 이야기 형식/일반 형식 토글
- 친구 초대 루프 1종 (로그인 없이 카드 1장)
- 지갑 (달빛/별조각, 모의 결제), 후속 질문 3회, 보관
- 카카오 + Google 로그인
- 읽을거리 (카드 해설·사주 개념 글 소량, SEO 뼈대)
- 관리자 최소 (원고, 상품, 원장 조회)

### 2차로 미룬다

실결제, 알림, PDF, PWA, 출석·추천인 보상, 애드센스 광고, 카드 78장 원화(MVP는 임시 카드 UI), 구독, 중·영·태 번역, 사용자 게시판(UGC).

## 4. 제품 구조와 데이터

| 묶음 | 내용 | 성격 |
|---|---|---|
| 계정 | 로그인 식별자(카카오·Google) 기준 사용자 | 공통 |
| 이야기(Story) | 사용자당 "나의 이야기" 1개로 시작 | 서사 뼈대 |
| 장(Chapter) | 리딩 1회 = 1장. 종류는 `사주 프롤로그`, `타로 장면`, `친구 장면` | 서사 뼈대 |
| 리딩 원자료 | 타로: 덱·정역·자리·조건. 사주: 입력 프로필·명식 스냅샷·계산 정책 버전·엔진 버전 | **사실. 서버가 확정, 수정 불가** |
| 서사 텍스트 | 요약본·상세본, 근거로 쓴 원자료 ID, 생성 버전 | **표현. 사실을 바꾸지 못함** |
| 후속 질문 | 장별 3회 | 공통 |
| 지갑 원장 | 지급·예약·차감·복구·환불 기록. 유상(달빛)과 무상(별조각) 구분 | 공통 |
| 주문 | MVP는 모의 결제 | 공통 |
| 초대 링크 | 소유자, 대상 장, 불투명 토큰 | 바이럴 |
| 게스트 참여 | 로그인 없이 뽑은 카드 1장, 승인 상태, 이후 계정 연결 | 바이럴 |
| 친구 장면 | 소유자가 승인한 것만 이야기에 노출 | 바이럴 |
| 글(Article) | 읽을거리 원고, 검수 상태 | 콘텐츠 |

원칙:
1. 카드와 명식은 서버가 확정한 사실이다. AI 서사는 그 위의 표현이며 사실을 바꾸지 못한다.
2. 다음 장을 쓸 때 AI가 참조하는 것은 **사용자가 실제로 본 이전 장의 요약과 직접 입력한 내용뿐**이다. 가상의 추억을 만들지 않는다.
3. 사주 장과 타로 장은 같은 이야기 안에 나란히 놓되 결론을 합치거나 점수화하지 않는다.
4. 출생정보·고민 원문·인증 토큰은 URL에 넣지 않는다.

## 5. 결제와 재화

### 결제 수단 선택 (심층 열기 화면)

사용자가 한 화면에서 고른다.

1. `바로 결제하고 보기 [금액]` — 건바건. 내부적으로는 충전 후 즉시 차감으로 원장을 거친다.
2. `달빛으로 보기 [수량]` — 유료 재화 차감. 부족하면 부족분 충전 후 열기.
3. `별조각으로 보기 [수량]` — 무료 재화 차감 (가입 선물 등).

- 세 방법 모두 열리는 상품의 품질·후속 질문·보관 범위가 같다 (기획서 P3).
- 결제 엔진은 하나(원장 1개)이고 UI 버튼만 여러 개다.
- 재화가 건바건보다 약간 저렴하면 충전을 유도한다. **할인율은 설정값**이며 출시 전에 정한다.
- 무료 재화는 재화 버튼에서 먼저 소진된다. 유상분과 원장에서 구분해 기록한다 (기획서 P10).
- 충전 성공과 상세 접근권한 부여는 별개 사건이다 (기획서 D21).

### 가격 (미확정, 참고 앵커)

2026-09-29에 공식 페이지를 직접 열어 본 값이다. 앱스토어 인앱 목록은 요약 도구가 추출한 값이라 대략치다.

| 서비스 | 확인한 값 | 출처 |
|---|---|---|
| 사주도령 | 상품 카드에 **990원**, 고민 상담 330원 | doryeong.app 직접 열람 |
| 오늘의 마음 타로 | AI 심층 해석 1회 **1,900원**, 신규 가입 시 1회 무료 | onulmaumtarot.kr 직접 열람 |
| 사주아이 (별도 서비스) | 990원 | 검색 결과와 후기 글 (직접 열람 아님) |
| 기획서 v0.3 후보 | 2,900원 / 3,900원 (10크레딧) | 확정 가격 아님 |

한국 저가 앵커(990~1,900원)보다 기획서 후보가 높지만, 시장 가격은 하나가 아니라 층이 있다. 사용자가 스레드에서 관찰한 2~3만원대 판매 사례가 있고(직접 확인하지 않은 관찰), 리뷰 글에는 22,000원 궁합 서비스가 "상세하지만 덮고 나면 기억에 안 남는다"는 평으로 나온다. 가격 하나로 경쟁하지 않고 사다리로 설계한다.

| 층 | 상품 | 가격 |
|---|---|---|
| 무료 | 첫 요약, 오늘의 한 장, 가입 선물 심층 1회 | 0원 |
| 표준 심층 1회 | 후속 3회·보관·이야기 형식 포함 | 2,900원대 (시안 예시) |
| 프리미엄 종합 리포트 | 사주 프롤로그 확장판, 연간 흐름 등 **범위를 명시**한 상위 상품 (기획서 P3의 확장 상품) | 2~3만원대 검토 |

- 모든 가격은 **설정값**이며 출시 후 실제 전환율로 조정한다. 데스크 리서치만으로는 지불 의사를 맞출 수 없다.
- 가격은 실제 AI 호출 비용을 재서 원가 이상인지 확인한 뒤 확정한다.
- MVP 구현은 표준 심층까지이며, 프리미엄 리포트는 상품 구조(범위 표시)만 준비하고 2차에 연다.
- 그때까지 시안의 금액은 예시다.

### 결제 시 확인할 것

PG 수수료와 최소 결제금액(건바건은 결제 건수가 많아 영향이 큼), 재화 환불·유효기간·미사용 잔액 처리는 구현 전에 토스페이먼츠 약관과 공식 문서로 확인한다. 법률 의견이 아니라 출시 전 확인 항목이다 (기획서 P17).

## 6. 화면과 흐름

시안 11장: 모바일 9(홈, 질문 만들기, 카드 뽑기, 무료 결과와 열기, 로그인, 열린 장, 내 이야기, 내 정보, 친구 화면) + 웹 1(3열 레이아웃) + 화면 흐름도 1. 톤은 남보라 밤하늘 위에 은은하게 반짝이는 별과 별자리 선을 깔고, 스토리 카드는 종이 질감의 밝은 카드로 둔다. 별은 일부만 천천히 깜빡이며 `prefers-reduced-motion`에서는 멈춘다.

### 화면 목록

| 화면 | 핵심 |
|---|---|
| 홈 | 큰 버튼은 `타로 보기`(주 행동), `사주 보기`(보조) 둘뿐. 내 이야기가 맨 위, 오늘의 한 장(로그인 없이), 친구 장면, 가이드 |
| 질문 만들기 (1/3) | `누구`, `무엇`, `언제`를 눌러 문장을 만든다. 누구를 고르면 그에 맞는 주제만 보인다. 타로 / 사주 / 타로+사주 선택 |
| 카드 뽑기 (2/3) | 부채꼴 카드에서 3장을 직접 고른다. 자리 이름(지금의 분위기 / 마음에 걸리는 것 / 앞으로의 흐름)이 위에 보인다. 3장을 고르면 `결과 보기`가 나타난다 |
| 무료 결과와 열기 (3/3) | 첫 카드 풀이 무료 공개 + 잠긴 목차. 처음 방문은 `로그인하고 무료로 보기`(가입 선물), 재방문은 `바로 결제 / 달빛 / 별조각` 3버튼 |
| 로그인 | 열기 직전에만 나타난다. 카카오 우선, Google 보조. 가입 선물 안내 |
| 열린 장 | 이야기/일반 토글, 카드별 풀이, `오늘 해볼 작은 행동`, `다르게 볼 수 있는 부분`, `근거 보기`, 후속 질문(남은 횟수), 친구에게 보내기 |
| 내 이야기 | 프롤로그(사주), 장(타로), 친구 장면(승인 대기). `새 장 열기`가 화면의 주 행동 |
| 내 정보 | 프로필, 내 재화(달빛·별조각)와 충전, 내 사주 정보(저장), 재화 내역, 친구 초대, 알림, 문의, 로그아웃 |
| 친구 화면 | 로그인 없이 카드 1장 → 자기용 짧은 결과 → "나도 내 이야기 시작하기" |
| 웹 | 좌측 메뉴(하단에 프로필과 재화), 가운데 이야기, 우측 다음 장 만들기. 같은 구성요소가 넓은 화면에서 재배치 |

하단 탭은 `홈 / 내 이야기 / 가이드 / 내 정보` 4개다. 지갑은 별도 탭이 아니라 `내 정보` 안에 있고, 상단의 재화 잔액을 누르면 그곳으로 간다.

### 흐름

1. 처음 방문: 홈 → 질문 만들기 → 카드 뽑기 → 무료 결과 → (로그인) → 열린 장 → 내 이야기
2. 친구 초대: 열린 장 → 보내기 → 친구 화면(로그인 없음) → 짧은 무료 결과 → (로그인) → 친구의 홈
3. 다시 방문: 내 이야기 → 새 장 열기 → 질문 만들기 → 카드 뽑기 → 열기(3버튼) → 열린 장

로그인은 **열기 직전**과 **저장·이야기 시작 시점** 두 곳에서만 요구한다. 다단계 화면에는 진행 표시(1/3, 2/3, 3/3)와 뒤로 가기를 둔다.

### 위계 규칙

- **화면마다 주 행동은 하나**이며 금색 채움 버튼으로만 표시한다. 보조 행동은 테두리 버튼, 셋째 행동은 글자만 쓴다.
- 글자 위계는 화면 제목(Gowun Batang 22~28) → 섹션 제목(17 굵게) → 본문(15) → 보조(13) 순이다. 탭 라벨만 12이다.
- 면은 하늘(배경) → 유리 카드(내용) → 시트(열기·결제) → 종이 카드(읽는 글) 순으로 밝아지며, 읽는 글이 가장 밝다.
- 터치 대상은 44px 이상, 본문·보조 글자는 대비 4.5:1 이상을 지킨다.
- 결제 시트에는 포함 범위(후속 질문 횟수, 보관)를 결제 전에 적어 둔다.

### 사용한 레퍼런스와 배운 점 (2026-09-29~30 확인)

- 사주도령: 상품 카드에 가격 표시, 하단 탭에 결과 보관, 입력 즉시 확인(`→ 1990년 1월 1일`), 시간 모름 버튼, 우상단 메뉴. 넓은 화면에서 약 448px 고정 컬럼으로 보였음(직접 확인). 프로필 자리를 어떻게 두는지는 메뉴를 열어 보았으나 내용을 확인하지 못했다.
- 점신 App Store 미리보기: 오늘 운세를 큰 점수 숫자 + 한 줄 조언 + 날짜별 그래프로 보여 주고, 바로가기 칩(만세력 등)과 요일별 콘텐츠 목록이 있다(미리보기 이미지로 확인, 하단 탭 구성은 이미지에 없어 확인하지 못함).
- Co-Star 디자인 비평(Pratt IXD): 화면당 행동 하나와 명확한 CONTINUE는 장점이다. 진행 표시·뒤로 가기 부재, 작은 하단 탭 글자, 모호한 아이콘, 유료 화면의 정보 부족은 단점으로 지적됐다. 이를 진행 표시, 라벨 있는 탭, 시트의 포함 범위 표기로 반영했다.
- ui-ux-pro-max 스킬(로컬 데이터 검색): 글라스 스타일 수치(블러 10~20px, 반투명 10~30%, 1px 테두리), 감속 모션 존중, 한 화면에서 움직임은 소수만 쓰라는 지침을 참고했다. 신비·점술 팔레트는 데이터에서 찾지 못해 직접 정한 팔레트를 썼다.

### 로그인 시점

기획서 D5는 질문 입력 뒤 바로 로그인한다. 이 설계는 **무료 요약을 본 뒤, 심층 열기 또는 저장 시점으로 미룬다.** 스레드·카톡 인앱 브라우저에서 로그인이 막히면 첫 화면에서 이탈하기 때문이다. 대신 로그인 전에 뽑은 카드는 짧게 사는 불투명 복원 토큰으로 서버에 고정하고, 로그인하면 계정으로 이어 붙인다. 무료 요약은 편집 원고나 캐시로 처리하고 세션별 비용 예산을 둔다 (기획서 D5).

카카오 로그인은 카카오 개발자 앱 등록과 키 발급이 필요하다. 카톡 공유(기획서 D13)도 같은 앱 키를 쓴다. 동의 항목 등 세부 조건과 Supabase의 카카오 로그인 지원 여부는 구현 전에 공식 문서로 확인한다. 키는 채팅에 붙이지 않고 연결 도구나 정식 인증으로 전달한다.

### 질문 만들기와 품질 연결

조합 UI는 자유로워 보이지만 `대상 × 주제 × 시점` 조합을 **미리 정의한 스프레드 템플릿 5~6종**에 매핑한다. 카드 자리의 의미가 정해져 있어야 풀이가 구체적이고 일관된다 (기획서 D2, D3). `누구`를 고르면 그에 맞는 `무엇`만 보인다(나 / 나와 그 사람 / 나의 일 / 우리 모임). 주제 예: 연애운, 썸·고백, 재회·연락, 재물운, 직업·이직, 학업·시험, 인간관계, 갈등·화해, 건강·컨디션, 마음·감정, 이사·선택, 창작·도전, 오늘의 운. 모두 흐름과 관점만 다룬다. 재회 확률, 합격 보장, 투자 종목·수익, 질환 진단, 타인의 속마음 단정은 다루지 않는다 (기획서 D2).

## 7. 훅과 무료 범위

목표는 첫 사용자가 무료로 **구체성을 확인**하고 결제 여부를 판단하게 하는 것이다.

- 로그인 없이 첫 1회 요약 (오늘의 한 장 포함).
- 심층 열기 화면에서 **첫 번째 카드 풀이를 완결된 문단으로 무료 공개**하고, "선택한 상황"을 함께 표시해 입력이 반영됐음을 보인다.
- 나머지 카드 풀이, 카드 사이의 연결, 다르게 볼 부분, 오늘 해볼 행동은 **소제목 목록만** 보여준다. 흐리게 가린 가짜 글이나 실제로 만들지 않은 결과를 숨겨두는 방식은 쓰지 않는다 (기획서 D5, 미끼 결론·가짜 희소성 금지).
- 가입 선물로 심층 1회를 무료(별조각)로 준다. 비용은 캠페인 한도로 관리한다.

근거: 사주도령은 귀인지도·캐릭터 진단·오늘의 운세를 무료로 열고 유료 풀이로 잇는다. 오늘의 마음 타로는 로그인 없이 첫 1회, 로그인 시 하루 3회, 가입 시 심층 1회를 무료로 준다 (둘 다 직접 열람). 사주핑의 "답변마다 기본/깊은 풀이 선택"은 검색 요약 기준이며 화면은 직접 확인하지 못했다.

## 8. 리딩 생성과 정확도

### 파이프라인 (타로·사주 공통)

1. **확정(서버):** 타로는 덱·정역·자리·조건을 확정. 사주는 입력 정규화 → 만세력 계산 → 명식 스냅샷(엔진 버전·정책 저장). AI는 이 단계를 바꾸지 못한다.
2. **근거 묶음:** 확정된 카드/명식, 검수된 카드·명리 지식, 사용자 입력 조건, 사용자가 실제로 본 이전 장 요약.
3. **해석 개요(구조화):** 핵심 관점, 근거 연결(카드/명식 ID), 조건 반영, 다르게 볼 여지. 요약·상세·후속 질문이 이 개요 하나를 공유한다.
4. **서사 렌더:** 같은 개요를 이야기 형식과 일반 형식으로 만든다. 화면 토글이 이 둘을 바꾼다.
5. **자동 검사:** 없는 카드·명식 언급, 입력하지 않은 사실, 고위험 단정, 이전 장과의 모순, 지어낸 추억. 걸리면 재생성하거나 차단한다.
6. **저장:** 장으로 편입하고 장 요약을 저장해 다음 장의 재료로 쓴다.

### "잘 맞는"을 측정 가능한 셋으로 쪼갠다

예언 적중은 검증할 수 없으므로 아래로 품질을 관리한다.

- **계산이 맞다:** 만세력 골든 케이스(절기 경계, 윤달, 밤 11시 경계, 시간 모름, 음력 변환)를 자동 테스트하고, 엔진 2개 이상을 설정을 맞춘 뒤 교차 비교한다. 다수결로 정답을 정하지 않는다 (기획서 P6).
- **내 얘기 같다:** 결과에 "선택한 상황"을 표시하고, 같은 문장이 다른 질문에 반복되는지 검사한다.
- **안 뒤집힌다:** 재열람은 저장본을 복원하고 후속 질문은 같은 개요를 이어받는다.
- 결과 끝에 "얼마나 와닿았나요" 1탭을 두어 실제 체감을 잰다.

### 하이브리드 상세

타로 장은 명식 요약 3~5개 항목(일간, 오행 균형 등)만 근거 묶음에 추가한다. 결과에 카드 근거와 명식 근거를 따로 표시한다. 명식이 없으면 일반 타로로 동작한다.

### 모델

MVP 기본 모델은 1개다. 후보 2~3개를 같은 케이스로 비교하는 평가 도구를 처음부터 만든다. 모델 선택은 한국어 설명, 조건 반영, 카드 정합성, 일관성, 비용, 대기시간으로 한다 (기획서 D6).

## 9. 친구 참여 루프 (MVP 최소)

1. 내 리딩의 한 장면에서 "친구 초대" 링크를 만든다.
2. 친구는 **로그인 없이** 카드 1장을 뽑고 자기용 짧은 무료 결과를 받는다.
3. 친구가 남긴 장면은 내가 **승인한 것만** 내 이야기에 붙는다. 알림은 MVP에서 없고, 내가 접속하면 승인 대기 목록으로 보인다.
4. 친구 화면 끝에 "나도 내 이야기 시작하기"가 있다.

- 순위, 줄세우기, 관계 우열 표시를 쓰지 않는다 (기획서 P12). 귀인지도의 "지도가 채워지는" 경험과 관계를 긍정적 역할로 바꿔 부르는 방식만 참고한다.
- 공개되는 것은 닉네임과 짧은 결과뿐이다. 출생정보·전체 명식·개인 고민은 자동 공개하지 않는다.
- 친구 화면에서 로그인은 결과 저장이나 이야기 시작 시점에만 요구한다.
- 지표: 초대 → 참여 → 새 개설자 전환율을 처음부터 측정한다 (기획서 P18). 전파는 설계만으로 보장되지 않는다.

## 10. 콘텐츠와 SEO

공개 읽을거리(카드 해설, 사주 개념 글)로 검색 유입을 만든다.

- 운영자가 쓰는 매거진형이다. 사용자 게시판(UGC)은 신고·도배 관리 부담 때문에 MVP에서 제외한다.
- AI 초안을 쓰더라도 사람이 검수한 뒤 게시한다. 검색어만 바꾼 복제 랜딩을 대량 생산하지 않는다 (기획서 P13).
- 광고(애드센스)는 공개 읽을거리 페이지에만 붙이고 리딩·지갑·결제 화면에는 붙이지 않는다. 승인 조건과 스팸 정책은 도입 전에 Google 공식 문서로 확인한다. MVP에서는 광고를 넣지 않고 페이지 구조만 준비한다.
- 개인 리딩·명식·주문·초대 상세는 검색 노출 대상에서 제외하고 권한으로 보호한다.

## 11. 오류 처리와 복구

- 생성 실패 시 예약한 재화를 풀고 같은 장을 다시 열 수 있다. 재차감하지 않는다.
- 결제 콜백·웹훅이 중복돼도 충전은 한 번만 반영한다 (주문번호 기준 멱등).
- 두 기기에서 동시에 열어도 잔액이 음수가 되지 않는다 (원자적 예약).
- 후속 질문은 정상 저장된 응답만 횟수에서 차감하고, 재전송 요청은 같은 응답을 돌려준다.
- 로그인 전 카드는 복원 토큰으로 고정하고 새로고침·로그인 복귀에서도 바뀌지 않는다.
- 상세 결과는 권한이 확인된 뒤에만 서버가 내려준다. CSS로 가리는 방식은 쓰지 않는다.

## 12. 테스트

- **자동:** 만세력 골든 케이스, 카드 불변, 잔액 동시성, 결제 멱등, 타 계정 접근 차단(RLS), 생성 결과 검사(없는 카드·명식 언급 등).
- **품질:** 같은 케이스로 모델 후보 비교. 초기 검수 규모는 리딩 100, 후속 대화 30, 오류·결제 30 시나리오를 제안값으로 둔다. 타로 실무자 검수는 권장하며, 실제로 수행하기 전에는 "전문가 검수 완료"를 표시하지 않는다.
- **실기기:** 카톡, 스레드, 인스타 인앱 브라우저에서 로그인과 복귀를 확인한다 (기획서 D13).
- 자동 테스트로 통과한 범위와 사람이 검수한 범위를 따로 보고한다. 실행하지 않은 테스트를 통과로 표기하지 않는다.

- 결과 화면의 카드 폭은 100px 이상으로 하고 이름·번호·자리·정역을 표시한다. 뽑기 뒤에는 차례로 뒤집어 공개한다.

**상황 입력 단계 추가**
- 질문 만들기(누구·무엇·언제) 다음에 주제별 상황 칩 3~5개와 선택 한 줄 자유입력을 받는다.
- 결과에는 **입력받은 조건만** 보여준다. 입력받지 않은 장면(예: "밤")은 제목에도 만들지 않는다.

**스프레드 템플릿**
템플릿마다 자리 이름이 다르다.

| 템플릿 | 자리 |
|---|---|
| 관계·연락 | 나의 마음 / 두 사람 사이 / 먼저 움직이면 |
| 일·진로 | 지금 상황 / 막힌 곳 / 나아갈 방향 |
| 선택 | 이쪽을 고르면 / 저쪽을 고르면 / 놓치고 있는 것 |
| 나의 흐름 | 지금의 나 / 필요한 것 / 이 시기의 흐름 |
| 모임 | 모임의 분위기 / 나의 자리 / 도움이 될 태도 |
| 오늘의 한 장 | 1장 |

**무료 범위**
- 3장 모두 앞면을 공개하고, 자리별 한 줄 키워드를 무료로 준다.
- 첫 장은 250~350자로 완결된 풀이를 준다.
- 잠긴 목차는 실제 유료 소제목과 1:1로 맞춘다. 무료 문단을 유료본에 그대로 반복하지 않는다.

**유료 리딩 구조 (타로 기준 1,200~1,800자)**
1. 한 줄 결론
2. 카드별 풀이 (그림 속 상징 → 자리의 의미 → 내 상황 적용, 각 150~250자)
3. 세 카드의 연결 (번호·원소·메이저 비중)
4. 시기 (선택한 '언제'에 맞춤)
5. 상대 반응별 시나리오 (관계 템플릿)
6. 보낼 문장 예시 2개 또는 실행 예시
7. 피할 것
8. 다르게 볼 수 있는 부분
9. 오늘 해볼 작은 행동

이야기 모드는 같은 개요를 2인칭 서사 한 단락 이상으로 다시 쓴다.

**사주 흐름 화면 추가**
- 입력: 양력·음력·윤달, 생년월일, 태어난 시 또는 모름, 성별(대운 방향용), 출생 지역(기본 서울)
- 명식 확인: 네 기둥, 오행 분포, 일간, 적용한 계산 기준
- 프롤로그 결과
- 하이브리드용 명식 근거 블록
- 샘플 명식은 계산 엔진으로 검증한 값만 쓴다. 예: 1990-01-01은 일주 병인(丙寅), 일간 병화(lunar-javascript로 확인).

**문구**
- 제품 설명·시안 주석(예: "무료로 다 보여드려요", "금액은 예시예요", "같은 품질로 열려요")을 사용자 화면에서 뺀다. 첫 방문자가 모르는 '장' 용어 대신 "전체 풀이 보기"를 쓴다.
- 카드를 주어로 세우는 문장("은둔자는 ~라고 말해요")을 반복하지 않는다.

**추가할 상태와 화면**
첫 방문 홈, 빈 이야기, 카드 공개, 생성 대기, 생성 실패와 재화 복구 안내, 부족분 충전, 차감 확인, 게스트 결과, 친구 장면 상세, 공유 미리보기, 오늘의 한 장 결과, 가이드 글, 후속 질문 응답과 0회 상태, "얼마나 와닿았나요" 1탭.

**친구 화면**
뽑기 전 결과 예시(스포일러)를 없앤다. 주 행동은 "카드 뽑기"로 하고, 친구가 얻는 것(자기 결과)과 초대한 사람에게 남는 것을 함께 설명한다.

**위계**
토글의 활성 상태는 금색 채움이 아닌 밝은 면으로 표시해 주 행동 버튼과 겹치지 않게 한다. 사용자에게 보이는 글자는 12px 미만을 쓰지 않는다(탭 라벨만 12px).
