# 스타로그 SEO·AEO·GEO·색인 점검 (2026-10-08)

점검 대상은 가이드 `https://yeolmaeapps.kr`과 앱 `https://starlog.yeolmaeapps.kr`이에요. 읽기 전용 점검이라서 앱 코드를 고치지 않았고, 커밋도 서버 실행도 앱의 AI 호출도 하지 않았어요. 우리 호스트로 보낸 HTTP 요청은 40건이에요(요청 로그 `scratchpad/seo-audit/reqlog.txt`). 구글 PageSpeed 호출 3건은 쿼터 오류(429)로 막혔어요.

도구는 `ar-seo-audit` 스킬(`seo_checker.py`, `seo_health_scorer.py`), curl, nslookup, WebSearch, 공식 문서 확인(WebFetch)을 썼어요. 모든 판단에 근거(명령 출력, URL, 코드 줄)를 붙였고, 못 본 것은 "확인 불가"라고 적었어요.

## 1. 요약

1. **헬스 점수 72.6 / 100 (등급 C).** publisher 가중치로 54개를 점검했고 통과 30, 경고 19, 실패 5예요. 약한 카테고리는 이미지 62.5, 콘텐츠 70.0, AI 준비도 72.2예요(기술 75.0, 온페이지 75.0, 스키마 80.0). 성능은 PageSpeed 쿼터 소진(HTTP 429)으로 점수에서 뺐어요. 코어 웹 바이탈 3개가 전부 실패였다면 65.3, 측정한 대리 지표 3개만 넣으면 75.3이에요.
2. **점수에 안 보이는 가장 큰 병목은 "등록 0건"이에요.** 구글·네이버·빙 어디에도 소유확인과 사이트맵 제출이 없어요(14개 URL의 head에 확인 메타 없음, DNS TXT 없음). 색인된 페이지가 있는지는 **확인 불가**예요. 이게 풀리기 전에는 아래 개선이 트래픽으로 이어지기 어려워요. 스코어러는 항목을 똑같은 무게로 세서, 치명 항목 하나가 기술 점수의 1/16로만 반영돼요.
3. **기반은 단단해요.** canonical, 사이트맵, 리다이렉트(전부 1홉), JSON-LD(45/45 블록 파싱 성공), 글 머리 "요약" 블록(68/68편), 원전 쪽수 출처, 본문 중복 없음이에요.
4. **먼저 고칠 5가지**
   - HTTP→HTTPS 리다이렉트가 없어요(두 호스트 모두 200).
   - AI 학습 봇 규칙이 충돌해요(7개 토큰이 허용과 차단에 동시에 있고, 엣지는 403을 줘요).
   - 사이트맵 위생이 나빠요(미래 lastmod 3건, 본문이 거의 없는 랭킹 12쪽).
   - 큰 검색어를 맡은 글이 얇아요(`how-to-read-tarot` 1,021자 등 6편).
   - 카드 그림 alt가 전부 비었고, 글쓴이·검수 표기가 없고, Organization/WebSite 엔티티가 앱 호스트로 고정돼 있어요.
5. **확인하지 못한 것:** 코어 웹 바이탈(랩·필드), 실제 색인 상태, 진짜 봇 IP 기준 엣지 동작, 네이버 공식 제목·설명 글자 수, 백링크, 구글 리치 결과 테스트.

### 잘 되어 있는 것 (그대로 유지)

- 모든 표본 페이지가 canonical을 갖고(루트 `/`만 `/guide/tarot`을 가리켜요), 실수로 `noindex`가 걸린 곳이 없어요. 없는 글은 404와 `noindex`로 응답해요.
- 글마다 제목 바로 아래에 2~3문장 "요약"이 있어요. 중앙값 42어절이고, 67편이 60어절 이하예요. 답변 엔진이 그대로 가져가기 좋은 모양이에요.
- 카드 글마다 웨이트 원전 쪽수와 `/evidence` 링크가 있고, `/evidence`는 출처와 숫자를 공개해요. 템플릿으로 찍어 낸 글이 아니라 68편 본문이 서로 달라요(5-gram 유사도: 카드 최대 1.7%, 일간 최대 5.6%).
- `llms.txt`는 llmstxt.org 형식을 지키고, `rss.xml`은 RSS 2.0으로 68건이에요. IndexNow 키 파일은 200이에요.
- 푸터에 상호, 대표, 사업자등록번호, 통신판매업 신고번호, 주소, 이메일이 보여요.
- HTML TTFB 중앙값이 0.35초예요(14건, 최소 0.21, 최대 0.58).

## 3. 측정 방법과 한계

- **수집:** `scratchpad/tools/fetch.sh`로 curl 40건을 보냈어요(리다이렉트는 따라가지 않고 한 번에 하나씩). 응답 헤더와 본문을 `scratchpad/seo-audit/`에 저장했어요. 일반 페이지는 모바일 Chrome UA, 봇 시험은 해당 봇의 UA 문자열을 썼어요.
- **분석:** 저장한 HTML을 `seo_checker.py --file --json`(12쪽)과 직접 짠 오프라인 분석기(`scratchpad/tools/analyze.py`: 메타, canonical, JSON-LD 파싱, 링크, 이미지)로 봤어요. 글 길이와 중복은 `llms-full.txt`에서 68편을 잘라 계산했어요. 크롤러 접근은 robots.txt를 직접 파싱해 규칙 병합 방식별로 계산했어요(`robots_eval.py`).
- **공식 문서로 확인한 것:** RFC 9309(규칙 병합), 구글 크롤러·AI 기능·사이트맵·FAQ 문서, OpenAI·Anthropic·Perplexity 봇 문서, Cloudflare 관리형 robots.txt 문서. 쓴 내용은 아래 해당 절에 그대로 적었어요.
- **확인 불가:** 코어 웹 바이탈(PSI 429), 실제 색인, 진짜 봇 IP 기준 엣지 동작, 네이버 공식 글자 수(서치어드바이저 페이지는 WebFetch가 막혀서 못 봤고, 검색 결과는 2차 자료뿐), 백링크, 구글 리치 결과 테스트(로그인 필요), 검색량과 SERP 경쟁 상황, `/ranking`·`/lucky`·`/how`·`/help` 본문(요청 예산 때문에 안 받았어요).

### 7.1 크롤러별로 실제로 받는 것

robots.txt는 Cloudflare 관리 블록이 먼저 오고(`# BEGIN Cloudflare Managed content` ~ `# END`), 그 뒤에 앱 그룹이 와요. 두 쪽에 같은 크롤러 이름이 있으면 해석이 파서마다 갈려요.

- **병합하는 파서**(RFC 9309 §2.2.1: "the matching groups' rules MUST be combined into one group", 구글도 같은 방식, 이 PC의 Python 3.13 `urllib.robotparser`도 같은 결과): 같은 이름의 두 그룹 규칙을 합쳐요. `Disallow: /`와 `Allow: /`는 길이가 같아서 §2.2.2("If an "allow" rule and a "disallow" rule are equivalent, then the "allow" rule SHOULD be used")에 따라 **허용**이 돼요.
- **첫 그룹만 읽는 단순 파서:** Cloudflare 그룹이 먼저라서 **차단**으로 읽어요.
- **엣지(Cloudflare):** 학습 봇 UA에 403을 줘서 robots와 상관없이 막아요.

시험은 내 IP에서 UA 문자열만 바꿔 `GET /guide/the-fool`을 보낸 거예요(진짜 봇은 IP 검증을 거치니 결과가 다를 수 있어요).

**충돌 해결 옵션** (소유자 결정이 필요해요)

- **옵션 A (기본 권장):** Cloudflare 관리 블록은 그대로 두고, 앱 `NAMED_CRAWLERS`에서 학습 전용 토큰 7개를 뺍니다. 모든 파서와 엣지가 같은 답(학습 봇 차단)을 내고 `ai-train=no`와 맞아요. 대가는 Google-Extended도 막힌다는 점이에요. 구글 문서상 이 토큰은 Gemini 앱의 학습과 그라운딩을 제어하고, 검색 포함·AI Overviews와는 무관해요. 그래서 Gemini 앱에서 인용될 가능성이 줄 수 있어요.
- **옵션 B:** Cloudflare의 "학습 차단 robots.txt"를 끄고(Security → Settings → Bot traffic → "Set your preference to block training in robots.txt"), `lib/robots.ts` 한 곳에서 관리합니다. Google-Extended만 허용하고 나머지 학습 봇은 직접 `Disallow` 그룹으로 막을 수 있어요. 대가는 Cloudflare가 갱신해 주는 봇 목록(지금 32개 토큰, 그중 7개가 앱 그룹과 겹쳐요)을 직접 관리해야 한다는 점이에요. 엣지 403은 AI Crawl Control에서 따로 유지해요.
- 어느 쪽이든 robots.txt 변경이 AI 검색에 반영되는 데 약 24시간 걸려요(OpenAI 문서).
