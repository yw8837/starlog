## 3. 상세

### QA-01 Critical: 운영 `/login`이 빌드 때 404로 굳어 있음

- **재현**
  1. `curl -sI https://starlog.yeolmaeapps.kr/login` → `HTTP/1.1 404`, `x-nextjs-prerender: 1`, `x-nextjs-stale-time: 300`. `/login?next=%2F`도 404
  2. 같은 시각 `/login/review` → 200. 이 페이지는 `STARLOG_PAYMENTS`가 owner/on일 때만 200이므로, 운영의 런타임 모드는 owner/on이 맞음
  3. 같은 커밋(72c35ec)의 게이트 빌드 산출물: `.next/prerender-manifest.json`의 `/login`이 `"compute":"static"`, `.next/server/app/login.meta`가 `"status": 404`, `login.html`에 "찾는 페이지가 없어요"
- **원인**: `app/login/page.tsx:13`이 `searchParams`를 await하기 전에 `if (paymentsMode() === "off") notFound();`를 실행함. 빌드 환경(게이트·`deploy.sh`)에는 `STARLOG_PAYMENTS`가 없어서 "off"로 판정되고, 빌드 때 프리렌더 단계에서 404가 정적으로 굳음. `app/login/review/page.tsx:15`는 `await connection()`을 먼저 해서 이 문제가 없음
- **영향**
  - 오늘: 오너 패스로도 `/login`에 못 들어감. 오너는 `/login/review`(심사 계정)만 써서 지금까지 못 봤을 가능성이 큼
  - 10/15 `STARLOG_PAYMENTS=on` 이후: 결과 시트 "로그인하고 전체 풀이 보기"(`/login?next=…`), `/me` "로그인하기", 비로그인 `/pay/checkout`(→`/login` 리다이렉트), `/api/auth/kakao/start`의 나이 미확인 리다이렉트(→`/login`)가 **전부 404**. 가입 선물·결제 출시가 막힘
  - 게이트에서 못 잡은 이유: 로그인·결제 e2e(`pay-flow.spec`)는 `pnpm dev`에서만 돌고, 프리뷰 e2e는 pay-flow를 뺌. 로컬 dev는 동적 렌더라 200
- **기대 vs 실제**: 기대는 런타임 owner/on 모드에서 `/login` 200. 실제는 운영에서 항상 404
- **수정 제안 (S)**
  - `app/login/page.tsx`: `import { connection } from "next/server"`, 맨 위에 `await connection();`를 넣은 뒤 `paymentsMode()` 판정. `login/review`와 같은 패턴
  - 재발 방지: `scripts/ops/gate3-lite.sh`의 cf:build 뒤에 `.next/server/app/login.meta`가 없는지 확인하는 체크를 추가하거나, 프리뷰를 `STARLOG_PAYMENTS=owner`로 띄워 `/login` 200을 확인. `scripts/ops/deploy.sh` 스모크 목록에 `https://starlog.yeolmaeapps.kr/login`(owner/on이면 200 기대)도 추가
  - 다른 페이지 점검: `paymentsMode()`/`salesOpen()`를 렌더 중에 읽는 페이지는 `app/login/page.tsx`, `app/login/review/page.tsx` 둘뿐(`grep`). `PaymentsNote`는 `/api/me`로 런타임에 읽어서 문제없음

### QA-02 Medium: 다른 기기에서 원래 풀이 주소를 열면 "이 기기에만 보관"이라고 나옴

- **증거**: `shots/ux-d-crossdevice-before-login.png`, `ux-d-crossdevice-after-login.png`, `out/crossdevice.json`
- **수정 (M)**: `app/chapter/[id]/LocalChapter.tsx:238-240`의 없음 분기에서 로그인 상태면 계정 기록(`/api/readings`)에서 로컬 id나 serverId로 찾아 이동시키고, 못 찾으면 "로그인했다면 내 기록에서 찾아보세요" + 내 기록 링크. 저장할 때 로컬 id를 계정 기록에도 남기는 게 가장 간단함(`lib/storage/sync.ts` 쪽). `app/story/StoryView.tsx:105` 문구는 로그인 상태면 "이 기기와 계정에 보관돼요"로

### QA-03 Medium: 공유 페이지에 고른 상황 칩이 그대로 나옴

- **재현**: 상황 칩 "지금은 수입이 없음"과 메모를 넣고 풀이 열기 → 공유 링크 만들기 → 다른 컨텍스트에서 `/s/rtaxezaa3s3v` 열기. 페이지 HTML에 `'지금은 수입이 없음'이라고 골랐으니 이 그림을…`이 있고, 메모 자리는 `메모에 '○○'라고 적었죠.`로 남음. 질문 문장("이번 주 내 재물 흐름은 어떨까?")은 안 나옴(정상)
- **기대 vs 실제**: 시트 안내는 "질문과 직접 쓴 말, 이어서 물어본 내용은 보이지 않아요". 칩은 직접 쓴 말이 아니라서 문구상 틀린 건 아님. 하지만 사용자가 실직·이별·재회 같은 민감한 상황 칩을 골랐다면 그게 그대로 공개되고, 그 사실을 미리 알려 주지 않음
- **원인**: `lib/share/payload.ts:56-66` `hideOwnWords`는 일부러 칩을 남김("The preset chips stay"). 시트 문구는 `components/share/ShareResultButton.tsx:25-28`
- **수정**: (S) 시트에 "고른 상황은 풀이 속에 보일 수 있어요" 한 줄 추가. (M) 공유본에서 조건 칩 값도 ○○로 가리고, "메모에 '○○'라고 적었죠"처럼 가린 말만 인용하는 문장은 통째로 빼기. 실제 모델 출력에서 칩을 얼마나 자주 인용하는지는 **측정 안 함**(mock만 봄)
