# 스타로그 카드(덱) 프로토타입 · 78장 타당성 메모

클래식(RWS 1909 스캔) 대신 고를 수 있는 **"스타로그 카드"** 후보다. 이 폴더에는 샘플 3장(0 바보 · I 마법사 · XVII 별)과 그 제작 도구가 있다. 앱 코드는 건드리지 않았다(§7은 목록만). 상태: 프로토타입, 사람 검수 전.

## 1. 결론

1. **된다.** 앱의 실제 캐릭터 컴포넌트를 그대로 가져와 SVG로 조립했다. 키트·파이프라인·카드 3장 초안·첫 비교 이미지까지 24분(파일 시각 17:02→17:26), 다듬은 최종 렌더까지 43분(17:45)이 걸렸다(사전 조사 약 10분 별도).
2. **메이저 22장은 장면별 제작**(완료 3 / 쉬움 3 / 보통 11 / 어려움 5), **마이너 56장은 시스템**(에이스 4 엠블럼 + 2~10 36장 scene-lite 템플릿 + 코트 16 = 랭크 템플릿 4 × 수트 스킨 4).
3. **노력**: 에이전트 작업 약 30~50시간 + 사람 검수 약 7~10시간 → 하루 6~8장씩 검수하면 2~3주(외삽, 오차 큼). 파일 용량은 78장 환산 약 8.7 MiB로 현재 스캔(14.7 MiB)보다 작다.
4. **리스크 상위**: ① AI 리딩이 KB의 `imageryFacts`(1909 그림 사실)를 인용하므로 덱별 facts가 필요하다(강아지 ↔ 토끼) ② 조연 동물·재색 변형의 일관성 ③ 90px에서 엠블럼 10개 가독성 ④ 역방향 = CSS 180° 회전 ⑤ 죽음·악마·탑의 톤.
5. 그림 78장보다 **앱·AI 쪽 결합**(§7)이 더 큰 일이다. 덱 선택 UI와 저장, 챕터 기록의 `deck`, KB 런타임·프롬프트·검증기가 걸린다.

## 3. 만든 방법 (78장에 그대로 쓸 파이프라인)

```
apps/web/components/characters/*.tsx ──(esbuild, 메모리 패치)──▶ tools/.build/parts.mjs
                                                                      │ react-dom/server
tools/cards/<id>.mjs (장면 = JS 템플릿 + 파츠) + tools/lib/kit.mjs ───▶ svg/<id>.svg
svg ──(Playwright, system Chrome)──▶ png 1x / 3x ──(sharp)──▶ webp 600w, sm 240w, 3x
```

- **파츠는 새로 그리지 않고 가져온다.** `CatHead` `CatEars` `CatTail`+`TailStar` `CatFeet` `CatPaw` `Cape` `AstrologerHat` / `RabbitHead` `RabbitEars` `RabbitFeet` `RabbitPaw` `Pencil` `Glasses` `Bow` 15개를 앱의 `.tsx` 그대로 `renderToStaticMarkup`한다. 그래서 얼굴·모자·안경·리본이 앱과 한 획도 다르지 않고, 캐릭터를 손보면 다시 빌드만 하면 덱이 따라온다.
- 이 중 `Cape` `AstrologerHat` `Pencil` `Glasses` `Bow`는 앱에서 export되지 않은 함수다. 번들할 때 **메모리에서만** `export {…}`를 덧붙여 꺼냈다(앱 파일 수정 0). 앱 쪽 리팩터링에 취약하므로 §6에 적었다.
- 새로 그린 것: 팔(캡슐 + 파츠 손), 토끼 가디건 몸통(`RabbitTarot`와 같은 path), 소품, 배경, 프레임.
- **글자는 윤곽**: Noto Serif KR 700(SIL OFL 1.1)에서 필요한 글리프 10개만 뽑아 path로 넣었다(`tools/glyphs.json`). 폰트 의존이 없어 어디서 열어도 같다.
- 외부 이미지·모델·타 덱 참조 없음. 구도·소품 모두 이 저장소의 캐릭터와 코드로 직접 구성했다(현대 덱을 따라 그리지 않음).
- 접근을 3가지 놓고 골랐다: ① 파츠 조립 SVG(채택) ② 전부 손으로 만든 SVG(배경·소품에만 사용) ③ 이미지 생성 모델(기각: 캐릭터가 장마다 달라지고, 수정·재현이 안 되고, 권리 확인이 어렵다).

### 스타일 규칙 (프로토타입에서 쓴 값)

- 캔버스 600×1040(앱 상자와 같아 `cover`에서 잘림 없음. 스캔은 1.70~1.80 비율이라 잘린다).
- 외곽선 없음. 그라디언트 + 오른쪽 위 광원의 림라이트 + 톤온톤 디테일선 **1.8~3.4px**, 프레임 **5px**(금) + 1.8px 헤어라인. 앱 파츠의 선(1.3~2.3 × 배율 1.3~1.7 = 1.7~3.9)도 대체로 이 범위에 들어온다.
- 팔레트: night `#0d0a26` · `#15113a`, navy `#2e2a78`, ink `#f1ecff`, gold `#f3dca1` / `#e9c46f`. 포인트는 코랄 `#d8435a`(복주머니·장미), 청록 `#43aa90`(잎), 연못 `#3652b8`.
- 카드마다 색 정체성: 바보 = 새벽 보라→복숭아, 마법사 = 밤 남색 + 금빛 오라, 별 = 밤하늘 남색→청. 부채꼴에서 한눈에 구분된다.
- 번호는 위 탭(y 18~88), 이름은 아래 탭(y 944~1022)으로 고정. 앱이 카드 모서리를 폭의 약 7%(600px 기준 약 42px) 둥글게 잘라내므로 프레임은 18px 안쪽에 두고 모서리 반지름을 26으로 했다. 주요 요소는 두 탭 사이(y 90~930)에 둔다.
- 카드 뒷면은 기존 `back.svg`를 그대로 쓴다고 가정했다(프레임을 `back.svg`의 금테·밤하늘 톤에 맞춤). 전용 뒷면은 범위 밖이며, 필요하면 같은 키트로 1장이다.

## 4. 확인한 것 / 못 한 것

확인(`tools/check.mjs` 통과):
- SVG 3장: 중복 id 0, 끊어진 `url(#…)` 0, `<text>` 0, `font-family` 0, 외부 참조 0, `script` 0. 렌더 15개 파일의 크기가 600×1040 / 240×416 / 1800×3120과 일치.
- 폭 90px(`legibility-90px.png`): 번호·이름 판이 읽히고(0, I, XVII, 바보, 마법사, 별), 카드의 핵심 상징(해와 모자 / 지팡이와 ∞ / 큰 별 + 작은 별)이 알아볼 만하다. 역방향(180° 회전)도 판만 뒤집힐 뿐 장면은 무너지지 않는다.
- RWS 상징 유지(KB `imagery.facts` 기준, 좌우 규칙 포함):
  - 바보: 절벽 끝(돌출 바위 턱 + 떨어지는 돌), 막대 끝 작은 보따리(복주머니), 흰 장미, 동행(토끼, 앞발 들고 뛰어오름), 오른쪽 위 해, 설산, 모자의 붉은 깃털.
  - 마법사: 오른손(보는 이 기준 왼쪽)의 위로 든 지팡이, 왼손으로 땅 가리킴, 머리 위 ∞, 탁자 위 컵·펜타클·칼·지팡이, 붉은 장미와 흰 백합, 위쪽 장미 넝쿨.
  - 별: 큰 별 1 + 작은 별 7(모두 8방향), 항아리 둘(하나는 연못, 하나는 땅), 땅으로 갈라지는 물줄기 5, 연못의 물결, 나무 위 새, 먼 산, 꽃 핀 풀밭, 연못에 오른발·땅에 왼 무릎.

RWS와 일부러 다르게 한 곳(스타로그용 imagery를 쓸 때 반영해야 한다):
- 바보: 동행이 **왼쪽 아래**(RWS는 오른쪽 아래). 오른쪽을 낭떠러지·구름·해에 쓰려고 바꿨다. 시선은 얼굴 파츠를 그대로 쓰느라 고개 기울임 + 윙크로만 표현했다. 초승달은 달토끼 모티프로 더한 것이다.
- 마법사: 붉은/흰 옷 대신 고양이의 남색 케이프, 허리 뱀 띠는 생략, 노란 배경은 금빛 오라.
- 별: 연한 하늘색 하늘 대신 밤하늘(브랜드 톤), 알몸 대신 가디건, 자세는 연못 쪽으로 기울인 무릎 꿇기의 근사치. 먼 언덕에 점성술사 고양이를 작게 앉혔다(덤).

**못 한 것**(정직하게):
- **앱 화면에 실제로 띄워 보지 않았다.** 앱 코드를 건드릴 수 없어서 `TarotCard.module.css`의 규칙(600:1040, `object-fit: cover`, 7~10px 라운드, 금 링)을 흉내 낸 HTML에서만 봤다. 실기기 DPR 2~3의 `srcset` 선택도 안 봤다.
- 마이너 아르카나, 조연 동물(말·스핑크스 등), 재색 변형 캐릭터는 만들지 않았다. §5의 해당 수치는 모두 **추정**이다.
- 사람 검수(RWS 상징 체크리스트, 리딩 품질)는 하지 않았다. 위 "RWS 상징 유지"는 내가 그림을 보고 KB와 대조한 것일 뿐이다.

알려진 아쉬운 점:
- 마법사: 가리키는 손가락과 손끝 반짝임을 키웠지만 90px에서는 "팔이 내려간 모양"으로 읽히는 쪽이다. 몸을 더 틀거나 손을 크게 그려야 한다.
- 바보: "하늘을 올려다봄"은 고개 기울임으로 근사했을 뿐이다. 오른쪽 아래 구름은 하단 비네팅 구간이라 약간 가라앉아 보인다.
- 별: 무릎 꿇기보다 "기울어 앉기"에 가깝다. 물줄기 5개는 읽히지만 뿌리처럼 보이기도 한다.
- 장미: 단순화한 꽃이라 90px에서는 붉은 점이다(위 상징은 큰 크기 기준).

### 5.2 마이너 56장: 시스템

핵심 판단: **핀(pip)만 늘어놓는 순수 시스템은 싸지만 리딩 품질이 떨어진다.** 앱의 AI 리딩은 카드 절의 첫 문장에 그림 사실(예: 검 10의 "엎드린 사람의 등에 꽂힌 열 자루")을 인용하고 검증기가 그걸 확인한다(§7-F). 그래서 2~10은 RWS처럼 **장면의 핵심 사실 하나는 남기는** scene-lite로 간다.

| 묶음 | 장 | 방식 |
|---|---|---|
| 공통 | – | 수트 스킨 4(배경 그라디언트·액센트·원소 분위기) + 엠블럼 4(완드·컵·검·펜타클은 마법사 카드에서 이미 그림) + 숫자 배치 템플릿 2~10 |
| 에이스 | 4 | 구름에서 나온 앞발이 엠블럼을 든다. 가장 쉬움 |
| 2~10 | 36 | 배경(수트 색) + **포즈 키트의 인물 1~3** + 숫자만큼 엠블럼. RWS의 핵심 사실 1개를 유지(예: 펜타클 5의 눈길을 걷는 둘, 완드 9의 붕대 감은 파수꾼) |
| 코트 | 16 | 랭크 템플릿 4(시종 = 서 있기, 기사 = 이동, 여왕·왕 = 착석) × 수트 스킨 4. 기본 캐스팅은 시종 = 토끼, 기사 = 고양이, 여왕 = 토끼, 왕 = 고양이(각 8장씩). 의상 색·소품·원소 배경으로 수트를 구분 |

### 5.3 먼저 만들 공통 키트 (한 번만)

1. **포즈 키트**: 서기·앉기·무릎 꿇기·걷기·달리기·눕기·거꾸로 매달리기·들어 올리기·가리키기 등을 매개변수(어깨·손·발 위치, 머리 기울기)로 만드는 `figures.mjs`. 지금은 카드마다 팔을 직접 그렸다. 78장이면 필수다.
2. **조연 변형**: 파츠가 `sl-cat-fur` 같은 그라디언트 id를 참조하므로, id 치환 + 그라디언트 정의 몇 개로 재색 고양이·토끼(검정·회색·갈색, 새끼 크기)를 만들 수 있을 것으로 본다(**미검증**).
3. **조연 동물 도감**: 말(죽음·태양·기사 4장 = 6장), 스핑크스(전차·수레바퀴), 가재·새·황소·독수리 정도. **새 디자인이라 일관성 위험이 가장 큰 곳**이다. 말 1종을 먼저 정하고 6장에 재사용한다.
4. **소품 라이브러리**: 별·구름·잎·장미·백합·리본(물줄기)·기둥·왕좌·탑·등불. 일부는 `kit.mjs`에 이미 있다.

### 5.4 시간·노력

기준: 도구·키트 + 카드 3장 초안 + 첫 비교까지 24분, 다듬은 최종까지 43분(키트와 카드 시간은 따로 재지 않았다). 키트가 있으면 카드당 10분 안팎이라는 감으로, 새 소품·포즈·조연이 늘어나는 점을 감안해 **2~3배**로 잡은 에이전트 작업시간이다(사람 검수 제외, 전부 추정).

## 8. 오너가 정해야 할 것

1. **죽음·악마·탑의 표현**(해골 없이 상징만? 어두운 변주?).
2. **마이너 방식**: scene-lite(권장, 리딩 품질 유지) vs 순수 핀(더 싸지만 첫 문장 인용용 그림 사실이 줄어든다).
3. **코트 캐스팅 기본안**(시종·여왕 = 토끼, 기사·왕 = 고양이) 승인.
4. **덱별 imagery 작성·검수 담당**과 일정(§7-F).
5. 기본값을 클래식으로 둘지, 신규 사용자에게 선택을 물을지.
