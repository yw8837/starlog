# 스타로그 카드 · STYLE.md (v2)

스타로그 카드의 그림 규칙이다. 프로토타입 v1(`prototype/`)에서 소유자가 "캐릭터가 커서 귀엽기만 하고, 핵심 상징이 작고, 배경이 복잡해서 카드 이름을 바로 맞히기 어렵다"고 해서 방향을 바꿨다. 이 문서의 모든 규칙은 한 가지를 위한 것이다. **직관성: 라벨을 가려도 타로를 아는 사람이 실루엣만 보고 카드 이름을 말할 수 있어야 한다.**

상태: 8장(0 바보 · I 마법사 · II~VI · XVII 별)으로 검증. **프레임 B 확정**(소유자 결정, `deck.json`의 `frame`), 조연 규칙 승인.

## 1. 원칙 다섯 줄

1. 1909 카드의 **구도·포즈·시선**을 그대로 쓴다(바꾸지 않는다).
2. 상징은 **크게, 적게**: 첫눈에 읽히는 상징(rank 1)은 카드당 5개 이하.
3. 배경은 **평면 색 3개 이하**. 구름·잎·무늬 같은 장식은 상징이 아니면 넣지 않는다.
4. 고양이·토끼는 **마스코트가 아니라 배우**다. 전신으로 장면을 연기하고, 머리 크기는 고정한다.
5. 모든 카드는 §5의 **자가 테스트 2종**(90px 스퀸트, 이름 맞히기)을 통과해야 한다.

## 2. 제작 방법: 원본 → 단순화 → 캐릭터화

한 장은 세 단계를 거치고, 단계마다 파일이 남는다. 리뷰 시트에는 세 단계를 나란히 보여 준다.

| 단계 | 하는 일 | 파일 |
|---|---|---|
| ① 원본 | 1909 스캔(`apps/web/public/cards/<id>.webp`)에서 인물의 위치·포즈·시선, 지평선, 핵심 사물을 읽는다. 상징을 순위 매긴다(아래) | `stages/<id>/1-original.webp` |
| ② 단순화 | ①의 구도와 실루엣을 그대로 두고 필수 상징만 **크게**, **평면 도형**(그라디언트·외곽선 없음)으로 다시 그린다. 인물은 사람형 도형. 군더더기는 버린다 | `stages/<id>/2-simplified.svg` `.png` |
| ③ 캐릭터화 | 인물을 **같은 관절 좌표**의 고양이·토끼로 바꾼다(머리는 앱 파츠 그대로, 몸·팔다리는 도형). 상징은 ②에서 정한 자리·크기 그대로. 프레임 A/B 두 벌 | `stages/<id>/3-character-A.svg` `.png`, `3-character-B.svg` `.png` |

- **관절 공유**: 카드 모듈(`cards/<id>.mjs`)의 `J` 객체에 목·어깨·손·엉덩이·무릎·발 좌표를 한 번만 정하고, `stage2()`(사람)와 `stage3()`(캐릭터)가 같이 읽는다. 그래서 ②와 ③의 포즈가 어긋나지 않는다.
- **상징 표시**: 상징 덩어리를 `sym(name, rank, markup)`으로 감싸고 모듈이 `symbols = [{name, rank}]`를 내보낸다.
  - rank 1 = 핵심(이름을 정하는 것. **카드당 5개 이하**, 배우(`actor`)도 하나로 센다), rank 2 = 보조, rank 3 = 배경(검사 안 함).
- **덱 마스터**: 활성 프레임 변수(`deck.json`의 `frame`)로 ③을 `svg/<id>.svg`로 복사하고, 거기서 `render/`(웹용 webp·png·3x)와 `print/`(인쇄용)를 만든다.
- 새 카드 만들기: `deck.json`에 카드 추가 → `python3 tools/make-glyphs.py`(새 글자 윤곽) → `cards/<id>.mjs` 작성 → `node tools/preview.mjs <id> all` → `node tools/selftest.mjs <id>` → 통과하면 `node tools/render.mjs <id>`.

## 4. 선·모양·프레임

- **외곽선 없음.** 단순화 도형과 새로 그리는 소품은 평면 색만 쓴다. 선이 필요한 곳은 모양으로 만든다(막대는 둥근 사각형, 물줄기는 리본).
- **선 굵기 규칙**: 프레임 금선 5px(밑에 night2 11px 밑선), 안쪽 헤어라인 2px(투명도 .5), 판 테두리 4px. 상징에는 **4px보다 가는 선을 쓰지 않는다**(90px에서 사라진다). 캐릭터 파츠 안의 선(수염, 발가락, 눈)은 앱 파츠가 정한 대로 둔다.
- **빛**은 오른쪽 위. 카드 안에 새 그림자·하이라이트를 따로 그리지 않는다(파츠가 가진 림라이트만).
- **안전창**: 핵심 상징은 `x 50~550, y 114~884`(`SAFE`) 안에 둔다. 위 번호 판 아래와 이름 판(B는 키워드 줄 때문에 더 높다) 위다.
- 모든 면은 캔버스 밖으로 **60 단위 이상 넘겨** 그려 인쇄 도련(3mm = 25.7 단위)을 덮는다(`bg()` 헬퍼).

## 5. 자가 테스트 2종 (모든 카드, 단계 ③에서)

### 5.1 90px 스퀸트 테스트 (자동, `node tools/selftest.mjs [id]`)

카드를 90×156으로 줄이고 흐리게(blur 0.8) 본 상태에서, `sym`으로 표시한 상징을 하나씩 숨겼을 때 달라지는 영역을 잰다.

| 순위 | 크기(90px 기준) | 밝기 대비 ΔL |
|---|---|---|
| rank 1 | 긴 변 ≥ 14 그리고 짧은 변 ≥ 7. 가는 막대형(지팡이)은 긴 변 ≥ 28, 짧은 변 ≥ 4 | ≥ 12 |
| rank 2 | 긴 변 ≥ 9, 짧은 변 ≥ 5. 막대형 ≥ 18 / 3 | ≥ 8 |

- **PASS** 통과, **WARN** 대비 부족(색을 바꾸거나 키운다), **FAIL** 너무 작다(단계 ②로 돌아가 키운다). FAIL이 하나라도 있으면 카드는 반려한다.
- 결과는 `review/selftest.json`. 흐린 90px 이미지는 리뷰 시트의 "squint" 줄에서 사람이 한 번 더 본다. 실루엣이 한 덩어리로 남는지, 큰 상징이 보이는지 본다.
- 한계: `sym`으로 표시하지 않은 요소는 검사하지 않는다. 그래서 이름을 정하는 상징은 빠짐없이 rank 1로 표시해야 한다.

### 5.2 이름 맞히기 테스트 (사람, "name-the-card")

`review/blind/<id>.png`는 번호·이름 판을 뺀 카드다. 타로를 아는 사람(타로 리더 또는 타로 공부 경험자)에게 **라벨 없이, 순서를 섞어** 보여 주고 "이 카드 이름이 뭐예요?"를 5초 안에 묻는다.

- **합격**: 3명 중 2명 이상이 정답. 카드당 기록은 `review/blind-test.csv`(열: `id,tester,answer,seconds,correct`)에 남긴다.
- 틀린 답은 가장 값진 자료다. "무엇과 헷갈렸나"를 보고 단계 ②에서 빠진 상징을 찾는다(예: 마법사를 은둔자로 읽었다면 ∞와 탁자가 작다).
- **현재 상태**: 3장 모두 작성자가 직접 본 자가 판정만 했다(편향이 있다). **맹검은 아직 안 했다.** 소유자가 지인 3명에게 `review/blind/`의 3장을 보여 주면 된다.

## 6. 프레임 두 변형과 타이포

모든 카드가 같은 프레임을 쓴다. `deck.json`의 `"frame"`이 덱 전체의 활성 변형이고, 지금은 **B**(소유자 결정)다. A로도 단계 파일(`stages/<id>/3-character-A.*`)이 같이 만들어진다.

| | A | B |
|---|---|---|
| 위 번호 판 | 같음: 금 로마 숫자(0, I, XVII…) | 같음 |
| 아래 이름 판 | 이름 한 줄 (높이 70) | 이름 + 가는 금선 + **키워드 한 줄** (높이 112) |
| 키워드 | 없음 | KB `content/kb/cards/<id>.json`의 `keywordsKo`에서 **그대로** 하나를 골라 `deck.json`에 적는다 (바보 "새 출발", 마법사 "의지와 실행", 별 "조용한 회복") |

- 바깥선: 금 5px가 가장자리에서 **36 단위(4.2mm)** 안쪽, 모서리 반지름 24. 판은 위/아래 선에 걸어 둔다. 판 모서리 반지름 22.
- **글자는 윤곽선**(폰트 의존 없음): Noto Serif KR(SIL OFL 1.1). 번호·이름 wght 700(번호 56, 이름 A 62 / B 54, 자간 0.06 / 0.2), 키워드 wght 500(25, 자간 0.05). 색 `goldLight`. 필요한 글자는 `deck.json`에서 모아 `tools/make-glyphs.py`가 `tools/glyphs.json`으로 만든다.
- 키워드는 지어내지 않는다. KB가 바뀌면 `deck.json`의 값도 같이 갱신한다.

## 7. 캐릭터

**머리는 절대 바꾸지 않는다.** 얼굴·귀·모자·안경·리본은 앱의 실제 파츠(`CatHead` `CatEars` `AstrologerHat` / `RabbitHead` `RabbitEars` `Glasses` `Bow` `Pencil`)를 그대로 쓴다. 바꿔도 되는 것은 몸통, 팔다리, 소품, 그리고 파츠를 가리지 않는 **추가** 액세서리(깃털, 후광, 왕관 띠)뿐이다.

| | 고양이 (타로 리더) | 토끼 (사서) |
|---|---|---|
| 모습 | 크림 털, 남색 뾰족 모자(달과 별, 꺾인 끝), 별 망토, 별 꼬리 | 흰 털, 동그란 금테 안경, 접힌 귀의 리본, 귀 뒤 연필, 라벤더 가디건(금 단추 둘, 흰 깃). **모자 없음** |
| 성격 | 능동·권위·실행·탐색 | 수용·지식·돌봄·치유 |
| 나오는 카드 | 마법사, 황제, 교황, 전차, 은둔자, 매달린 사람, 악마… | 여사제, 여황제, 힘, 절제, 별… |
| 둘이 함께 | 바보, 연인, 탑, 달 | |

- **비율**: 머리 스케일 1.0 고정(고양이 머리 폭 154 = 카드 폭의 26%). 전신 높이는 카드 높이의 50~60%. 팔다리는 둥근 끝의 캡슐(팔 반지름 18→14, 다리 22→16, 몸통 폭 120~132). 손발은 앱 파츠(`CatPaw` `RabbitPaw`)나 앱 발 모양. 머리 기울기 ±16° 이내.
- **의상 규칙**: 고양이는 역할 의상을 입는다(여행자 = 짧은 별 망토, 마법사 = 남색 로브 + 크림 속옷 + 금 허리띠와 금 소매 띠, 장화 = 산호색 + 금 띠). 토끼는 가디건이 기본이고 역할 의상은 가디건 위에 얹는다.
- **표정**: 앱 파츠가 가진 `idle` `happy` `focus` `surprise` `wink` 중에서 장면에 맞는 것(바보 = 윙크, 마법사 = 기본, 별 = 집중).
- 코트 카드 기본 배역(안): 시종 = 토끼, 기사 = 고양이, 여왕 = 토끼, 왕 = 고양이.
- **머리 장식**은 파츠 위에 더한다: 왕관·삼중관은 고양이 모자의 금띠(황제 = 보석 박힌 금관 띠, 교황 = 금띠 3겹과 늘어진 띠), 토끼는 귀 사이의 달 관(여사제)이나 별 관(여황제). 얼굴·귀·안경·리본은 가리지 않는다.

## 8. RWS의 조연을 다시 입히는 규칙

| RWS에 있는 것 | 스타로그에서 |
|---|---|
| 사람(주인공·군중) | **사람은 그리지 않는다**(②의 습작에서만 사람형). 고양이 또는 토끼로 바꾼다 |
| 군중·조연 인물 | 같은 두 캐릭터의 **변형**: 털색 3종(크림·회색·검정 / 흰·회색·갈색), 새끼는 0.5~0.6배. 머리 파츠는 그대로(색만 그라디언트 id 치환, `tools/lib/props.mjs`의 `recolor`). **V 교황의 수도자 둘(회색·검정 새끼 고양이)에서 적용·검증**. 수도자 역은 모자를 생략한다(삭발 대신) |
| 천사 | 날개 단 흰 토끼: 귀와 머리 파츠만(안경·리본·연필 없음), 회색 로브, 금 후광, 코랄 날개, 구름 위. **VI 연인에서 적용**. 악마 쪽은 박쥐 날개 달린 검은 고양이(승인, XV에서 적용) |
| 개(바보) / 늑대·개(달) | 토끼 / 고양이 변형 |
| 사자(힘) | 갈기 목도리를 두른 고양이 |
| 말(죽음·태양·기사) | 새 디자인 1종(흰 말, 이마의 별)을 한 번만 만들어 6장에 재사용 |
| 스핑크스(전차·수레바퀴) | 흑백 고양이 석상 |
| 새·가재·뱀 등 작은 동물 | 평면 아이콘(별의 새처럼) |
| 벌거벗음 | 망토·가디건·로브 |
| 해골(죽음) | **보류**: XIII에서 선택지를 보여 주고 소유자가 고른다. 상징 구조(흰 말, 검은 갑옷, 깃발의 흰 장미, 두 탑 사이 해)는 유지 |
| 글자(TORA, ROTA) | 쓰지 않는다. 상징으로 대신한다(별, 문양) |

## 9. 90px에서 RWS 상징이 읽히게 하는 규칙

1. 카드의 이름을 정하는 상징을 먼저 고른다(KB `imagery.facts` salience 1, 많아야 5개). 그것을 rank 1로 표시하고 가장 크게 그린다.
2. 상징은 **원본의 자리**에 둔다(오른쪽 위의 해, 한가운데 인물, 왼쪽 탁자). 위치도 상징이다.
3. 상징 사이에는 **빈 면**을 둔다. 겹치는 상징은 하나로 합쳐 읽히게 한다(막대와 보따리).
4. 바탕과 상징의 밝기 대비 ΔL ≥ 12. 밝은 하늘에는 어두운 인물(바보), 어두운 하늘에는 밝은 별(별).
5. 첫눈에 읽는 순서를 하나로: **대각선 하나**(마법사의 팔), **수평선 하나**(바보의 절벽, 별의 연못).
6. 번호·이름 판은 고정 위치·고정 크기. 읽기 쉬운 크기(번호 56, 이름 62)를 줄이지 않는다.
7. 키워드(B)는 작은 글자라 90px에서는 안 읽힌다. 키워드에 의존해서 이름을 알리지 않는다.
8. **크림색 상징은 밝은 바탕에서 사라진다.** 고양이의 손·얼굴이 상징의 일부일 때(교황의 축복 손) 바탕을 중간 명도 이하로 잡는다(교황: 보라 벽 `#6A63AC`). 금색 상징은 노랑·주황 바탕에서 밝은 금(`goldLight`)과 진한 금(`goldDeep`) 두 톤으로 나눠 그린다(황제의 앙크·구슬).
9. 숫자로 세는 상징은 90px에서 셀 수 있는 수로 줄인다(여황제의 별 12개 → 5개, 석류 무늬 → 큰 점).
