# 스타로그 카드 · PRINT.md

실물 덱(타로 70×120mm)으로 인쇄하기 위한 규격, 내보내기, 색 변환 메모, 인쇄소 체크리스트다. 앞면 78장 + 공용 뒷면 1장이 대상이다. 지금은 앞면 3장(바보·마법사·별)과 뒷면이 이 규격으로 나온다.

## 1. 규격

| 항목 | 값 | 카드 좌표(600×1040 기준) |
|---|---|---|
| 재단 크기(트림) | **70 × 120 mm** | 1mm = 8.571 단위 |
| 도련(블리드) | **3 mm** 사방 → 작업 크기 **76 × 126 mm** | 25.7 단위 |
| 안전선 | 재단선에서 **5 mm** 안쪽(핵심 상징·글자는 여기 안) | 42.9 단위 |
| 모서리 | 다이컷 R3 mm(인쇄소 확인) | 25.7 단위 |
| 재단 오차 가정 | ±1 mm | |

**아트 비율 문제**: 아트는 앱 상자와 같은 600:1040(= 70 × 121.33 mm)이라 재단 높이 120 mm보다 1.33 mm 크다. 내보낼 때 폭을 70 mm에 맞추고 **위·아래에서 0.667 mm(5.7 단위)씩** 자른다. 도련은 그 바깥으로 3 mm 더 이어 그린다(모든 장면이 60 단위 이상 넘겨 그려져 있다).

레이아웃 위치(재단선에서의 거리):

| 요소 | 좌우 | 위·아래 |
|---|---|---|
| 금 프레임 바깥 가장자리 | 3.9 mm | 3.2 mm |
| 프레임 중심선 | 4.2 mm | 3.5 mm |
| 핵심 상징 안전창(`x 50~550, y 114~884`) | ≥ 5.8 mm | ≥ 12.6 mm 위, ≥ 17.5 mm 아래 |

프레임은 장식선이라 안전선(5 mm) 바깥쪽 3~5 mm 띠에 둔다. 재단이 1mm 쏠려도 선은 남는다(가장 나쁜 쪽 2.2 mm). 그래도 쏠림이 보이는 것이 싫으면 §6의 전면 풀블리드 대안을 쓴다.

## 2. 내보내기

벡터 마스터는 `svg/<id>.svg`가 기준이다(글자는 윤곽, 외부 참조 없음, `check.mjs`가 검사). PNG·WebP는 마스터에서 나온 파생물이다.

```bash
node tools/export-print.mjs                 # 모든 svg → print/<id>_70x120mm_bleed3mm_300dpi.png
node tools/export-print.mjs --dpi 600 back  # 600dpi
node tools/export-print.mjs --guides back   # print/guides/: 재단선(빨강)·다이컷(자홍)·도련(하늘)·안전선(초록) 겹친 확인용
node tools/export-print.mjs --trim-only     # 도련 없이 70×120mm (화면 확인용)
node tools/check.mjs                        # 크기·dpi·알파 없음 검사
```

| dpi | 도련 포함(76×126mm) | 재단(70×120mm) |
|---|---|---|
| 300 | **898 × 1488 px** | 827 × 1417 px |
| 600 | 1795 × 2976 px | 1654 × 2835 px |

- 파일: sRGB 8비트 PNG, ICC 프로파일(sRGB) 포함, 알파 없음, 밀도 태그 300dpi. `print/guides/`의 가이드 이미지는 **인쇄소에 보내지 않는다**.
- 파일 이름: `<카드id>_70x120mm_bleed3mm_<dpi>dpi.png` (예: `major-17-star_70x120mm_bleed3mm_300dpi.png`), 뒷면은 `back_70x120mm_bleed3mm_300dpi.png`.
- **벡터 그대로 못 보내는 이유**: 마스터에는 앱 캐릭터 파츠가 쓰는 가우시안 블러 필터(볼터치, 림라이트)가 들어 있어 일러스트레이터·인디자인이 래스터로 바꾸거나 다르게 해석한다. 납품 형식은 300dpi 래스터(PNG, 필요하면 PDF에 내장)이고, 해상도를 더 올려야 하면 같은 마스터에서 다시 내보낸다. 3x 마스터(`render/*@3x.png`, 1800×3120)는 약 650dpi 상당이라 마케팅·확대에 쓴다.
- 현재 출력 확인: `print/back_70x120mm_bleed3mm_300dpi.png` = 898×1488, 300dpi, sRGB, 알파 없음(`check.mjs` 통과).

## 3. 색 변환 (sRGB → CMYK)

마스터 색은 sRGB다. 인쇄소가 쓰는 프로파일(FOGRA39, Japan Color 2001, GRACoL 등)이 아직 정해지지 않아서, 이 PC에 있는 SWOP 계열 프로파일 둘로 **어느 색이 인쇄 색역을 벗어나는지** 미리 봤다(`python3 tools/cmyk-report.py`, 상대 색도계 + 검정점 보정, ΔE는 CIE76).

batch 1(II~VI)에서 새로 쓴 장면 색: 따뜻한 색(여황제 하늘 `#F2D170`·쿠션 `#E0764A`·밀 `#E8B33A`, 황제 하늘 `#E8894F`·산 `#E9B03C`, 연인의 해 `#F6D060`)은 모두 **안쪽**(ΔE ≤ 1). 파랑·보라는 **벗어남**: 여사제 망토 `#6F9BE8`(13.5), 연인 하늘 `#7FA3EA`(12.3), 연인 산 `#8774D8`(22.8). 교황의 절제된 보라 벽 `#6A63AC`는 채도가 낮아 ΔE 3.5로 거의 그대로 간다. **새 장면은 채도를 낮춘 보라·파랑을 고르면 인쇄에서 덜 변한다.**

읽는 법:
- **금색·산호·초록·따뜻한 하늘은 안전하다.** 프레임과 글자의 금색(`gold` `goldLight`)은 CMYK로 거의 그대로 간다. 금속광은 CMYK로 못 낸다.
- **보라·파랑은 칙칙해진다.** `violet`은 `#5B4FB8`에서 `#55529E`로, 연보라는 회색기가 돈다. 마법사 카드(보라 바탕)와 별 카드의 물·언덕, 바보의 설산이 가장 눈에 띄게 변한다.
- **가장 어두운 남색은 자동 변환하면 회색이 된다**(`night` → `#131217`). 단, 이 프로파일은 같은 색을 CMYK **직접 지정**으로 정확히 낸다. 탐색 결과:

| 목표 | 직접 지정 CMYK(잉크합) | 인쇄 후 | ΔE |
|---|---|---|---|
| night `#0D0A26` | C100 M85 Y10 K75 (270) | `#0D0A27` | 0.8 |
| night2 `#15113A` | C100 M85 Y0 K65 (250) | `#131039` | 0.6 |
| navyDeep `#1C1850` | C100 M85 Y0 K50 (235) | `#1C184E` | 1.3 |

- 프로파일을 바꾸면 결과가 달라진다. 같은 팔레트를 Agfa RSWOP.icm으로 돌리면 금색도 ΔE 4~7로 조금 변하고 어두운 남색은 초록빛 회색이 된다(ΔE 17~26). 두 프로파일 모두 **보라·파랑·짙은 남색이 벗어난다**는 점은 같다. **인쇄소의 실제 ICC로 `cmyk-report.py`를 다시 돌려야 한다**(`PROFILES` 경로만 바꾼다).

### 대응 방침 (택일, 인쇄소 답에 따라)

1. **RGB 납품 + 인쇄소 변환**: 가장 간단. 보라·파랑이 위 표처럼 칙칙해지는 것을 소유자가 승인한다. 반드시 디지털 프루프로 확인한다.
2. **대체색으로 마스터를 맞춘 인쇄판 만들기**: 표의 "인쇄 후" 색으로 팔레트를 바꿔 같은 SVG를 한 번 더 빌드한다(화면용 sRGB 마스터는 그대로). 화면과 실물이 가장 가깝다. 아직 구현하지 않았다(팔레트가 `kit.mjs`의 `C`와 카드별 상수에 있어 치환 표 한 장이면 된다).
3. **CMYK 직접 지정 + 확장 색역 인쇄**: 어두운 남색 바탕을 위 직접 지정값으로, 보라는 확장 색역 디지털 인쇄(HP Indigo 등)나 별색으로. 비용이 오른다.

## 4. 금박(포일) 옵션

프레임·번호·이름 판의 금색을 박(호일)으로 하면 CMYK의 한계를 벗어난다. 이를 위해 **금색 요소만 검정으로 뽑은 박 마스크**가 따로 필요하다(프레임 그룹이 `<g id="frame">`으로 분리돼 있어 만들 수 있다). 아직 만들지 않았다. 인쇄소가 박 가공을 한다고 하면 추가한다.

## 5. 카드 뒷면

- `svg/back.svg`: 위쪽 그림을 한 번 그리고 중심(300, 520)을 기준으로 180° 돌려 한 번 더 그린 **점대칭**. 3배 렌더를 180° 돌려 비교하면 5,616,000픽셀 중 94개만 차이가 40/255를 넘는다(가장자리 안티앨리어싱). 역방향 카드가 뒷면으로 방향을 드러내지 않는다.
- 모티프: 로고 별(오각별) 위·아래, 초승달 위·아래, 중앙 메달리온의 팔각 별(별 카드), 별가루.
- 바탕은 전면 어두운 남색이라 재단·정합 오차(±1~2mm)가 보이는 곳은 금 프레임뿐이다. 카드마다 프레임의 좌우 여백이 조금씩 달라 보일 수 있다(§6 샘플 확인). 신경 쓰이면 프레임을 없애고 전면 풀블리드 문양으로 바꾼다.
- 웹용: 앱의 기존 `/cards/back.svg`(600×1020)를 대체하려면 `render/back.webp`(600×1040)나 `svg/back.svg`를 쓴다(비율이 20 단위 다르므로 `object-fit: cover`가 위아래를 조금 자른다).

## 6. 인쇄소 체크리스트

보내기 전에 확인하고 답을 `docs`나 이 파일에 남긴다.

**규격**
- [ ] 트림 70×120 mm가 가능한가(표준 타로 규격 목록에 있나)? 재단 오차는?
- [ ] 도련 3 mm, 안전선 5 mm가 맞나? 인쇄소 템플릿(다이라인)을 받는다.
- [ ] 모서리 둥글림 반지름(R3 가정). 칼선 파일이 따로 필요한가?
- [ ] 앞면 78 + 뒷면 1(공용) 구성이 가능한가? 뒷면은 점대칭이라 방향 표시가 필요 없다.

**파일**
- [ ] 받는 형식: PNG / PDF / TIFF? RGB(sRGB)로 받나, CMYK만 받나?
- [ ] 해상도 300dpi(898×1488)로 충분한가, 600dpi를 원하나?
- [ ] 인쇄소의 **ICC 프로파일**을 받아 `tools/cmyk-report.py`를 다시 돌려 §3 표를 갱신한다.
- [ ] 총 잉크량 한도(TAC): 우리 짙은 남색은 직접 지정 시 235~270%다. 한도가 280 이하인지.
- [ ] 어두운 남색을 직접 CMYK로 지정할 수 있나(§3 표). 안 되면 자동 변환 시 회색이 된다는 것을 안내한다.

**재료·가공**
- [ ] 용지 두께(300~350 gsm 안팎), 코어 색(검정/흰/파랑 코어: 가장자리에 보이는 선), 질감(린넨/매끈), 코팅(무광/유광/에이큐어스).
- [ ] 금박(§4), 모서리, 포장(박스, 설명서)을 할 수 있나? 박스 규격은 카드 76×126 mm 이상.
- [ ] 앞뒤 정합 오차와 재단 오차에서 프레임이 쏠려 보이는 정도(샘플로 확인). 싫으면 프레임을 6 mm 안쪽으로 옮기거나 전면 풀블리드 패턴으로.

**교정과 납품**
- [ ] **디지털 또는 하드 프루프 1벌**(78 + 뒷면)을 받아 보라·파랑 변화와 어두운 남색을 소유자가 승인한다.
- [ ] 최소 수량(MOQ), 단가, 납기, 재인쇄 시 색 편차.
- [ ] 카드 가장자리 부채꼴 확인(앞면 90px 가독성은 `review/`의 시트).
- [ ] 판매 전 표기: 클래식 RWS 1909는 퍼블릭 도메인, 스타로그 카드는 오리지널(그림·구도·코드 모두 이 저장소에서 직접 제작, 글꼴은 OFL 윤곽).

## 7. 아직 안 한 것

- 인쇄소 확정 전이라 **실제 프로파일 변환은 못 했다**. §3은 SWOP 계열 두 프로파일의 추정이다.
- 박 마스크, 인쇄 팔레트 치환(§3-2), 박스·설명서 디자인은 범위 밖이다.
- 프루프 출력을 받아 본 적이 없다. 화면(sRGB)과 종이의 차이는 샘플로만 알 수 있다.
